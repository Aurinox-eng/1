# Таблетки против бактерий (Pills vs Bacteria)

Казуальная HTML5-игра для публикации на **Яндекс Играх**. Владелец проекта — не программист: технические решения
принимаются самостоятельно и коротко объясняются простыми словами (по-русски), без жаргона.

## Принятые решения (кратко; правила — `docs/td-rules.md`, журнал — `docs/decisions.md`)
- **Tower defense:** поле **горизонтальное 1280×720**, красная линия («организм») **слева**, бактерии идут справа налево по
  дорожкам; башни стоят в клетках рядом с дорожками, сами стреляют, **у башен разные способы стрельбы** (по радиусу, по площади,
  одна цель, вперёд/назад…); игрок только ставит и улучшает башни. Деньги — за убитых бактерий. Уровни с победой. Все пять типов
  бактерий остаются. В итоге ≈10 башен; глубина — улучшения в партии + большое постоянное дерево за «антитела».
- **Боты и проверки — только через субагентов** (`qa-tester`, `game-designer`); владельцу в конце этапа — **одна итоговая
  таблица** («Что сделано / Проверка / Результат / Что нужно от вас»), без логов и чисел бота.
- Обойма отвергнута навсегда. Дерево улучшений: проект в `docs/upgrades.md`, без кода, ждать «ок» (этап 6).
- Phaser 3.90 (не обновлять до 4), TypeScript, Vite; графика и звуки — кодом, без внешних файлов.
- Баланс — только `src/config.ts`; тексты — только `src/i18n.ts` на RU и EN.

## Команды
| Команда | Что делает |
|---|---|
| `npm install` | установить зависимости (один раз) |
| `npm run dev` | игра для разработки: http://localhost:5173 (с телефона в той же Wi-Fi — адрес `Network:`) |
| `npm run build` | проверка типов + ИГРОВАЯ сборка в `dist/` (уйдёт на Яндекс; режима `?qa` в ней нет) |
| `npm run build:qa` | ТЕСТОВАЯ сборка в `dist-qa/` (с режимом `?qa`; в неё играют проверки и бот) |
| `npm run preview` | посмотреть собранную игровую версию |
| `npm run typecheck` | только проверка типов |
| `npm run qa -- --tag=<этап>` | обе сборки + проверка в браузере, скриншоты в `qa/screenshots/<этап>/`; ~2–3 мин; `--only=phone-ru` — один сценарий. **Запускает `qa-tester`** |
| `npm run qa:bot -- --runs=5 --speed=2 ...` | бот играет и замеряет баланс. **Запускает `game-designer`.** Сейчас написан под СТАРУЮ игру; под tower defense — на этапе 3 |

Нужен Chromium: в облаке уже есть; у себя — один раз `npx playwright install chromium`.
**Боты — по одному, `--speed` не выше 2** (иначе замер искажается).

## Правила проекта (обязательно)
1. **План → одобрение → код.** Крупные решения сначала согласуются с владельцем.
2. **Баланс — только в `src/config.ts`** (скорости, частоты, очки, паузы), комментарии на русском, с единицами измерения.
   Башни и улучшения — строками таблиц (данные), не разбросаны по коду.
3. **Тексты — на русском и английском** в `src/i18n.ts` (без перевода проект не соберётся); строк-надписей в коде сцен нет.
4. **Графика рисуется кодом**, без внешних картинок.
5. **Конец каждого этапа:** сборка → прогон `qa-tester` → скриншоты → команда, по которой владелец сам поиграет; затем коммит
   и push в рабочую ветку `claude/serene-rubin-x3t2gu`. **Pull request — только по просьбе владельца.**
6. Владелец следит из приложения Claude: файлы для него класть внутри проекта (скриншоты — в `qa/screenshots/`).
7. **Боты и проверки (`npm run qa`, `qa:bot`) запускают только субагенты; главный агент не запускает их и не пересказывает
   сырой вывод.** Владельцу — только итоговая таблица (см. «Принятые решения»). Быстрая `npm run typecheck` при написании
   кода остаётся у главного агента, в отчёт владельцу не идёт.

## Субагенты (`.claude/agents/`)
- **game-designer** — проектирует и настраивает баланс tower defense (башни, бактерии, волны, экономика, улучшения), правит
  только `src/config.ts` и `docs/`, замеряет ботом (бот под tower defense — этап 3). Переписан на этапе 0.
- **qa-tester** — запускает игру в браузере (Playwright), проверяет консоль, делает скриншоты, код не правит. Сценарии
  `qa/smoke.mjs` пока под старую игру — переписываются на этапе 1.
- Определения агентов подхватываются только при старте сессии: в текущей сессии новые инструкции давать в самом промпте.

## Публикация (GitHub Pages)
При каждом обновлении `main` workflow `pages.yml` собирает игровую версию (`npm ci` → `npm run build`; упала сборка — ничего не
публикуется) и выкладывает `dist/` на https://aurinox-eng.github.io/1/ (+ `version.txt` с коммитом и временем). Это для пробной
игры; на Яндекс Игры игра уходит zip-архивом (этап 9). Однократные настройки Pages — в README.md. Ветка `claude/...` не публикуется.

## Режим проверки (?qa)
`/?qa&speed=4&cfg=bacteria.startSpeed:120&lang=en` — открывает состояние игры для тестов, ускоряет время, подменяет числа
`config.ts`. Работает **только** при `npm run dev` и в тестовой сборке; в игровую не попадает (проверка `qa/smoke.mjs`).
Важно для этапа 9: иначе рекорд и рекламу можно накрутить из адресной строки. Подробности — `docs/technical-notes.md`.
