# Таблетки против бактерий (Pills vs Bacteria)

Казуальная HTML5-игра для публикации на **Яндекс Играх**. Владелец проекта — не программист: технические решения
принимаются самостоятельно и коротко объясняются простыми словами, без жаргона.

## Игра
Бактерии медленно опускаются сверху. Игрок тапом (телефон) или кликом (компьютер) стреляет таблеткой снизу вверх.
Таблетка летит строго вверх из точки тапа по горизонтали. Попал — бактерия уничтожена (+очки). Бактерия коснулась
красной линии внизу — проигрыш. Каждые 30 секунд скорость и частота бактерий растут. Партия — 30–60 секунд.
Экран вертикальный 9:16 (игровое поле 720×1280, масштабируется под любой экран).

## Технологии
Phaser 3.90 (третья версия! не обновлять до 4) + TypeScript + Vite. Графика рисуется кодом, звуки — синтезом (WebAudio),
внешних картинок и звуковых файлов нет, пока владелец не скажет иначе.

## Команды
| Команда | Что делает |
|---|---|
| `npm install` | установить зависимости (один раз) |
| `npm run dev` | запустить игру для разработки: http://localhost:5173 (с телефона в той же Wi-Fi сети — адрес `Network:` из вывода) |
| `npm run build` | проверить типы и собрать ИГРОВУЮ версию в `dist/` (именно она уйдёт на Яндекс; режима `?qa` в ней нет) |
| `npm run build:qa` | собрать ТЕСТОВУЮ версию в `dist-qa/` (с режимом `?qa`; в неё играют проверки и бот) |
| `npm run preview` | запустить собранную игровую версию (как она будет на площадке) |
| `npm run typecheck` | только проверка типов, без сборки |
| `npm run qa -- --tag=<этап>` | собрать обе версии + проверка в браузере (телефон и компьютер, RU/EN, поворот, два пальца, игровая сборка), скриншоты в `qa/screenshots/<этап>/`; занимает ~2 минуты; `--only=phone-ru` — один сценарий |
| `npm run qa:bot -- --runs=5 --speed=2 --tps=3 --error=25 --reaction=0.3` | собрать тестовую версию, бот играет как человек и замеряет длину партии (для подбора баланса) |

Для проверок нужен Chromium: в облачной среде он уже установлен; на своём компьютере один раз выполните
`npx playwright install chromium`.

## Правила проекта (обязательно)
1. **План → одобрение → код.** Крупные решения сначала согласуются с владельцем.
2. **Баланс — только в `src/config.ts`**: скорости, частоты, очки, паузы. В коде игры «магических чисел» баланса быть
   не должно. Комментарии в конфиге — на русском, простыми словами, с единицами измерения.
3. **Тексты — на русском и английском.** Любая надпись добавляется в `src/i18n.ts` сразу в обоих языках
   (без перевода проект не соберётся). Никаких строк-надписей прямо в коде сцен.
4. **Графика рисуется кодом** (фигуры, SVG, сгенерированные текстуры), без внешних картинок.
5. **Конец каждого этапа**: сборка → прогон `qa-tester` → скриншоты → команда, по которой владелец сам поиграет.
   Затем коммит и push в ветку `claude/pills-bacteria-game-plan-1frwn6`. Pull request — только по просьбе владельца.
6. Владелец следит за проектом из приложения Claude: файлы для него класть внутри проекта (например, скриншоты в
   `qa/screenshots/`).

## Субагенты (`.claude/agents/`)
- **game-designer** — предлагает и настраивает баланс, правит только `src/config.ts`, проверяет ботом.
- **qa-tester** — запускает игру в браузере через Playwright, проверяет консоль, делает скриншоты, код не правит.

## Публикация (GitHub Pages)
При каждом обновлении `main` workflow `.github/workflows/pages.yml` собирает игровую версию (`npm ci` →
`npm run build`, то есть с проверкой типов; если сборка упала, ничего не публикуется) и выкладывает `dist/` на
https://aurinox-eng.github.io/1/ (плюс файл `version.txt` с коммитом и временем сборки). Это только для
пробной игры и показа: на Яндекс Игры игра уходит отдельным zip-архивом (этап 5). Работает потому, что в
`vite.config.ts` пути относительные (`base: './'`) — игра открывается из подпапки `/1/`. Однократные настройки
на стороне GitHub (Pages → Source: GitHub Actions; репозиторий должен быть публичным или на платном тарифе) —
в README.md. Публикуется только `main`: рабочая ветка `claude/...` на Pages не выкладывается.

## Режим проверки (?qa)
Открывает состояние игры для тестов и позволяет ускорять время и подменять числа из `config.ts`:
`/?qa&speed=4&cfg=bacteria.startSpeed:120`; параметр `?lang=en` принудительно выбирает язык.
Всё это работает **только** при `npm run dev` и в тестовой сборке (`npm run build:qa`). В игровую сборку
(`npm run build`) этот код не попадает вообще: проверка `qa/smoke.mjs` убеждается, что в ней нет `?qa`,
подмены `?cfg=` и `?lang=`. Это важно для этапа 4: иначе рекорд и рекламу можно было бы накручивать из адресной
строки. Бот и проверки при устаревшей сборке (код изменился после неё) останавливаются с подсказкой.

## Важные технические решения
- Поле 720×1280 (9:16), режим масштабирования FIT: помещается целиком на любом экране, по краям — тёмные поля.
- Стрелять можно тапом по любой точке экрана, в том числе по тёмным полям вокруг поля (на высоких телефонах
  нижняя полоса — там, где лежит палец). Положение по горизонтали берётся из точки нажатия.
- Несколько одновременных касаний (`activePointers: 3`): у каждого пальца своя пауза между выстрелами
  (`pill.cooldownMs`), считается по реальным часам — на слабом телефоне пауза не растягивается.
- Попадание считается честно: таблетка (прямоугольник, растянутый на путь за кадр) касается круга бактерии.
- Защита от случайного рестарта после проигрыша (`gameOver.restartLockMs`) тоже по реальным часам
  (`performance.now`): игровые часы отстают, когда кадры тормозят.
- Один кадр не длиннее 50 мс в расчётах движения — после сворачивания вкладки бактерии не «прыгают»;
  если кадр длинный, за него может появиться несколько бактерий (не больше 10).
- Поворот телефона и смена окна: Phaser иногда знает новый размер страницы, но не перестраивает поле
  (воспроизводилось в эмуляции), поэтому `main.ts` сам вызывает пересчёт после `resize`/`orientationchange`.
- Звуковая система Phaser выключена (`audio.noAudio` в `main.ts`), пока в игре нет звуков: иначе браузер
  пишет предупреждение про AudioContext. **На этапе 3 эту строку убрать** и запускать звук по первому тапу.
- В игровой сборке нет режима проверки и подмены языка через адрес; язык — по настройкам браузера
  (на этапе 4 главнее будет язык из SDK Яндекса).

## Баланс: замеры
Бот (`qa/bot.mjs`) играет в 3 профилях. Значения `config.ts` на конец этапа 1; условия замера: `--speed=2`,
6 партий на профиль, три бота одновременно на 4-ядерной машине.
| Профиль | тапов/с | промах прицела | реакция | длина партии (медиана; от–до) |
|---|---|---|---|---|
| новичок | 2 | ±40 px | 0.45 с | ≈ 46 с (45–56) |
| средний | 3 | ±25 px | 0.30 с | ≈ 65 с (62–66) |
| сильный | 4 | ±15 px | 0.20 с | ≈ 100 с (96–120) |

Как читать: типичный неопытный игрок (профиль «новичок») укладывается в цель 30–60 с. Опытные играют дольше:
средний доживает до второго повышения сложности (60-я секунда), сильный — до третьего (~90-я секунда). Если
хочется, чтобы партия у всех была короче, усиливать надо второе и третье повышение (`difficulty.*`).
Осторожно с `--speed`: на больших значениях кадры игры «грубее», бот тапает реже, чем задано, и замер
занижает сильных игроков (так, при `--speed=4` «сильный» выходил ≈ 68 с — это было искажение замера).
Бот — приблизительная модель: окончательно баланс проверяется на живых игроках.
