## Принятые решения (кратко; журнал — `docs/decisions.md`)
- **Переход на жанр tower defense** (решение владельца, сессия перехода): вместо старой игры (падающие бактерии, тап-выстрел; она в истории: коммит `3b913a3`) — башни стоят в клетках и стреляют сами, бактерии идут по кривым дорожкам со слияниями и разветвлениями (сеть «корни») от правого края к организму слева; игрок только ставит, сливает и улучшает башни; деньги — за убитых бактерий; у башен разные способы стрельбы; уровни с победой; в итоге ≈10 башен (цель творческой итерации — 22–24).
- **Концепция:** уровень (30 волн) не проходится с первого раза без улучшений вне партии: помогают очки ДНК и улучшения (экран «Улучшения» после партии). Цель сложности — `docs/difficulty-plan.md`.
- Новые бактерии выходят редко (раз в 3–6 волн); тяжелее — числом бактерий, не новыми типами; волны не облегчать. Дефляция: больше бактерий не даёт больше денег. Башни открываются по уровням, открытая однажды башня доступна на всех уровнях (новый порядок открытия — часть 4, после замера). Вместо плашек — экран «Альманах».
- **Решение владельца 18 октября 2026:** во время партии игра не объясняет и не советует (что делает бактерия или башня, где и как строить) — это игрок узнаёт в Альманахе; остаются подсказка слияния, строка проигрыша «Больше всего жизней отняла: …», уведомления «Новая бактерия: <название>» и «Открыта башня: <название>». Камера на развилку остаётся.
- Пауза затемняет поле, строить в паузе нельзя. После конца уровня перезапуск только кнопкой «Заново». Башни выбираются в нижней панели с прокруткой; карточка выбранной башни — над панелью.
- Повтор пройденного уровня: очки за волны ×0,1, бонус за победу и звёзды — один раз (правило В); в режимах «Тяжёлый» и «Эпидемия» ×0,1 не действует (у режима свой множитель ДНК).
- **Решения владельца 18 октября 2026 (поздний вечер):** стиль графики пилота и глаза у таблеток — да, перенос на все виды (`docs/art-style.md`); мелкий размер (радиус < 20) — упрощённое лицо; `damageX` внесён по таблице открытия; ответы на раздел 7 плана части 4: ρ = 1; новые семейства врагов — на уровнях 6–10 (на 1–5 прежнее правило); «Лихорадка» первой, «Адреналин» и переключатель развилки после неё; «Лимфоузел» не вносить; «Аптека» — фиксированная сумма за волну; устойчивость — с уровня 6; названия боссов рабочие; карты уровней 2–4 — макетами до кода; Гигант на 30-й волне уровня 2, замер лестницей (`docs/decisions.md`).
- **Боты и проверки идут через GitHub Actions**, отдельные чаты не нужны. Владельцу — таблица «Что сделано / Проверка / Результат / Что нужно от меня» в конце каждой части, без логов и чисел бота. Новый режим бота — сначала одна пробная партия.
- **Баланс башен:** Лампа — детектор, одиночная башня уровень не выигрывает. До новой кривой башни сравнивать с выключенным ростом (`--cfg levels.specs.N.growth.latePerWave:0`, N = 4 для уровня 5, 5 — уровня 6, 9 — уровня 10), после «ок» — на новой кривой.
- Обойма отвергнута навсегда. Phaser 3.90 (не обновлять до 4), TypeScript, Vite; графика и звуки — кодом, без внешних файлов; тексты — русский и английский.

## Правила проекта (обязательно)
1. **План → одобрение → код.** Крупные решения сначала согласуются с владельцем (что делается без «да» и что требует «да» — правило 10).
2. **Баланс — только в `src/config.ts`** (комментарии на русском, с единицами измерения). Башни и улучшения — строками таблиц (данные).
3. **Тексты — на русском и английском** в `src/i18n.ts` (без перевода проект не соберётся); строк-надписей в коде сцен нет.
4. **Графика рисуется кодом**, без внешних картинок.
5. **Конец каждого этапа:** сборка → проверки на GitHub (`checks.yml`) → снимки → команда, по которой владелец сам поиграет; затем коммит и push в рабочую ветку. **Pull request — только по просьбе владельца.** После слияния PR рабочую ветку начинать заново от `main`.
6. Владелец следит из приложения Claude: файлы для него класть внутри проекта (снимки прогонов — `qa/screenshots/`, она в `.gitignore`; снимки в репозитории не хранятся: решение владельца 16 октября 2026, папка `docs/screenshots/` удалена, в истории git снимки остались).
7. **Боты и проверки — только через GitHub Actions** (`balance.yml`, `checks.yml`; `docs/bot-prompts.md`). Замер запускает агент: файл `.github/balance-request.json` + push в рабочую ветку, либо `actions_run_trigger` (workflow `balance.yml`, `ref` — рабочая ветка); итог — лог задачи «Итоговая таблица» (`get_job_logs`), сырые JSON — вложения прогона.
   **Локально в контейнере агента `npm run qa`, `qa/smoke.mjs`, `qa/bot.mjs` не запускать** (машина слабая: ложные красные, зависания); локально — только `npm run typecheck` и сборки. Число партий не экономить. Push в рабочую ветку запускает `smoke` (правки только в `docs/` и `*.md` — нет) и отменяет идущий; push с `[skip ci]` в сообщении последнего коммита `smoke` не запускает и идущий не отменяет (правило 10).
   Файл `.github/balance-request.json` сейчас содержит пробный запрос; любое его изменение в push запускает замер.
   Чтение замера: инструменты GitHub (`mcp__github__*`) подгружаются через ToolSearch; итоговая таблица — артефакт `bot-results-all` (`summary.md`): `actions_list` (`list_workflow_run_artifacts`) → `actions_get` (`download_workflow_run_artifact`) → скачать `curl` в отдельную пустую папку; сырые JSON партий — рядом (`results/qa/bot-results`).
8. **Производительность** (решение владельца): кадры в секунду из GitHub Actions **не считать результатом** (там нет видеокарты). В облаке сравнивать только «до/после» (`perf.yml`, одна машина) и время расчётов на кадр; **итог — замер владельца по `?fps` на компьютере, iPhone и iPad** (`docs/performance.md`).
9. **Секреты** (решение владельца 14 октября 2026): ключи Яндекса (SDK, API) и любые пароли, токены, ключи API, личные данные — **только в GitHub Secrets** (Settings → Secrets and variables → Actions), в workflow — через `${{ secrets.ИМЯ }}`; **никогда** в коде, `src/config.ts`, `docs/`, примерах запросов и сообщениях коммитов. Перед публикацией (этап 9) и перед каждым слиянием в `main` — проверка на секреты (последняя: 14 октября 2026, секретов нет; в метаданных 24 коммитов личная почта владельца — `docs/decisions.md`). **Почта в коммитах** (решение владельца 15 октября 2026): коммиты идут с адресом `335224071+Aurinox-eng@users.noreply.github.com`; закреплён `.claude/settings.json` (хук `SessionStart`, `GIT_AUTHOR_EMAIL`/`GIT_COMMITTER_EMAIL`), workflow `identity.yml` и этим правилом; в начале работы проверить `git config user.email`. Предупреждение стоп-хука («Unverified», рекомендация `noreply@anthropic.com`) ожидаемо и не выполняется: «Verified» не нужна, адрес не менять, историю не переписывать (подробности — `docs/technical-notes.md`, «Места на сервере и адрес в коммитах»). **Авторские права:** `LICENSE` — «Copyright (c) 2026 Aurinox. All rights reserved.», использование без письменного разрешения запрещено.
10. **Темп работы** (решение владельца 18 октября 2026; заменяет прежние «`smoke` после каждого коммита» и «не пушить во время `smoke`»; журнал — `docs/decisions.md`):
    - **Пачки.** Код — отдельными коммитами, как раньше; `smoke` — один на пачку готовых коммитов. Упала группа — искать коммит по названию группы; перебор коммитов — только если причина неясна.
    - **Отправка без ожидания.** Коммиты в контейнере не держать: push с `[skip ci]` в сообщении последнего коммита (проверки не запускаются и идущий `smoke` на той же ветке не отменяется — проверено 18 октября 2026, `docs/technical-notes.md`). `smoke` на готовой пачке — вручную (`workflow_dispatch`, поле `ref` — полный хеш). Правило «не пушить во время `smoke`» действует только для push без `[skip ci]` (он запускает новый прогон и отменяет идущий).
    - **Плавающие проверки.** Первое падение — один перезапуск. Повторное — короткий разбор: связано ли с новым кодом. Не связано — запись в список плавающих (`docs/technical-notes.md`, «Плавающие проверки») и работа дальше; список чинится пачкой раз в 2–3 дня. (За 17–18 октября на починку проверок ушло 23 коммита из 118.)
    - **Без «да» владельца:** исправления по уже принятым спискам; починка проверок; ускорение и экономия памяти без видимых изменений; переделка кода без изменения поведения; замеры и серии ботов (числа — через `--cfg`, `src/config.ts` не трогать); документы. **«Да» нужно для:** чисел баланса в `src/config.ts`; видимых изменений графики и интерфейса; текстов игры; новых механик и контента; слияния в `main`.
    - **Отчёт владельцу.** Первая строка — «Решения не нужны» или «Нужно ваше решение: N вопросов»; вопросы — с вариантами и рекомендацией; дальше таблица «Что сделано / Проверка / Результат / Что нужно от меня». Пока ждёшь ответа — работать по задачам, которые решений не требуют.
    - **Ночь.** Перед паузой в работе ставить долгие задачи (серии ботов, полные замеры), чтобы они шли, пока владельца нет.

## Команды
| Команда | Что делает |
|---|---|
| `PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1 npm install` | установить зависимости (в облаке) |
| `npm run dev` | игра для разработки: http://localhost:5173 |
| `npm run build` / `npm run build:qa` | проверка типов + игровая сборка `dist/` (режима `?qa` нет; уйдёт на Яндекс) / тестовая `dist-qa/` (с `?qa`) |
| `npm run typecheck` | только проверка типов (быстро) |
| `node qa/perf.mjs` | замер скорости в стресс-сценарии; **на сервере идёт сам (`perf.yml`, сравнение с `.github/perf-base`), локально не запускать** |
| `npm run qa -- --tag=<имя>` | обе сборки + `smoke`; **на сервере идёт сама, локально не запускать** |

`node qa/ladder-sets.mjs --attempts=1` (набор улучшений 1-й партии по модели очков ДНК; чистый расчёт, но нужен `npm install`) — можно запускать локально.

Структура папок и устройство кода — `docs/technical-notes.md`. Все числа баланса — `src/config.ts`. Счётчик кадров `?fps` — во всех сборках. Режим `?qa` (`/?qa&speed=4&cfg=раздел.параметр:число&lang=en&level=5&noplaque&canvas&stress`) — только `npm run dev` и тестовая сборка; `?level=N` работает и в игровой.
Пример: `?qa&cfg=economy.rewardCurve.2.1:0.3` (точка кривой наград).
