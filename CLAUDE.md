## Принятые решения (кратко; журнал — `docs/decisions.md`)
- **Переход на жанр tower defense** (решение владельца, сессия перехода): вместо старой игры (падающие бактерии, тап-выстрел; она в истории: коммит `3b913a3`) — башни стоят в клетках и стреляют сами, бактерии идут по кривым дорожкам со слияниями и разветвлениями (сеть «корни») от правого края к организму слева; игрок ставит, сливает и улучшает башни; деньги — за убитых бактерий; у башен разные способы стрельбы; уровни с победой; в итоге ≈10 башен (цель творческой итерации — 22–24).
- **Концепция:** уровень (30 волн) не проходится с первого раза без улучшений вне партии: очки ДНК и улучшения (экран «Улучшения» после партии). Эксперт-человек 18 октября: слишком легко — цели сложности пересматриваются (`docs/balance-rework-plan-2026-10-18.md`, `docs/difficulty-plan.md`). Правило «Уровень 1 не менять до попыток людей» снято.
- Новые бактерии выходят редко (раз в 3–6 волн); тяжелее — числом бактерий и прочностью, не новыми типами. Дефляция: больше бактерий не даёт больше денег. Башни открываются по уровням (новый порядок — часть 4, после замера `--solo=fizz`). Вместо плашек — экран «Альманах».
- Во время партии игра не объясняет и не советует (решение 18 октября 2026): остаются подсказка слияния, строка проигрыша «Больше всего жизней отняла: …», уведомления «Новая бактерия: …» и «Открыта башня: …».
- Пауза затемняет поле, строить в паузе нельзя; после конца уровня перезапуск только кнопкой «Заново». Повтор пройденного уровня: очки за волны ×0,1, бонус за победу и звёзды — один раз.
- Стиль графики пилота (вариант Б, глаза у таблеток) утверждён и перенесён на все виды в ветке стиля; ρ = 1 для бонуса рекорда, «Лихорадка» первой из умений, «Лимфоузел» не вносить, устойчивость с уровня 6, карты 2–4 макетами до кода (`docs/decisions.md`, 18 октября, поздний вечер).
- **Темп работы** (18 октября 2026): правило 10 ниже. Боты и проверки — только GitHub Actions.
- Обойма отвергнута навсегда. Phaser 3.90 (не обновлять до 4), TypeScript, Vite; графика и звуки — кодом, без внешних файлов; тексты — русский и английский.

## Правила проекта (обязательно)
1. **План → одобрение → код.** Крупные решения сначала согласуются с владельцем (что делается без «да» и что требует «да» — правило 10).
2. **Баланс — только в `src/config.ts`** (комментарии на русском, с единицами измерения). Башни и улучшения — строками таблиц (данные).
3. **Тексты — на русском и английском** в `src/i18n.ts` (без перевода проект не соберётся); строк-надписей в коде сцен нет.
4. **Графика рисуется кодом**, без внешних картинок.
5. **Конец каждого этапа:** сборка → проверки на GitHub → снимки → команда, по которой владелец сам поиграет; затем коммит и push в рабочую ветку. **Pull request — только по просьбе владельца.** После слияния PR рабочую ветку начинать заново от `main`. Полный текст — `docs/project-rules-details.md`.
6. Владелец следит из приложения Claude: файлы для него класть внутри проекта (снимки прогонов — `qa/screenshots/`, она в `.gitignore`; снимки в репозитории не хранятся: решение владельца 16 октября 2026, папка `docs/screenshots/` удалена, в истории git снимки остались).
7. **Боты и проверки — только через GitHub Actions** (`balance.yml`, `ladder.yml`, `checks.yml`, `perf.yml`; `docs/bot-prompts.md`). Запуск: `actions_run_trigger` (`ref` — ветка) либо файл `.github/balance-request.json` + push. **Локально в контейнере `npm run qa`, `qa/smoke.mjs`, `qa/bot.mjs` не запускать** (слабая машина: ложные красные); локально — `npm run typecheck` и сборки. Число партий не экономить. Push в ветку запускает `smoke` (кроме правок только в `docs/`, `*.md` и файлах публикации) и отменяет идущий; push с `[skip ci]` — нет (правило 10). Чтение итога серии, лимит мест (14 для серий из 20) — `docs/project-rules-details.md`, `docs/technical-notes.md`.
8. **Производительность** (решение владельца): кадры в секунду из GitHub Actions **не считать результатом** (там нет видеокарты). В облаке сравнивать только «до/после» (`perf.yml`, одна машина) и время расчётов на кадр; **итог — замер владельца по `?fps` на компьютере, iPhone и iPad** (`docs/performance.md`).
9. **Секреты** (решение владельца 14 октября 2026): ключи Яндекса и любые пароли, токены, ключи API, личные данные — **только в GitHub Secrets** (`${{ secrets.ИМЯ }}`), никогда в коде, `src/config.ts`, `docs/`, примерах запросов и сообщениях коммитов; проверка на секреты — перед публикацией (этап 9) и перед каждым слиянием в `main`. **Почта в коммитах:** `335224071+Aurinox-eng@users.noreply.github.com` (закреплена `.claude/settings.json` и `identity.yml`; в начале работы проверить `git config user.email`); предупреждение стоп-хука «Unverified» не выполнять, историю не переписывать. `LICENSE` — «Copyright (c) 2026 Aurinox. All rights reserved.» Подробности — `docs/project-rules-details.md`.
10. **Темп работы** (решение владельца 18 октября 2026; журнал — `docs/decisions.md`, полный текст — `docs/project-rules-details.md`):
    - **Пачки:** код — отдельными коммитами; `smoke` — один на пачку; упала группа — искать коммит по названию группы.
    - **Отправка без ожидания:** коммиты не держать; push с `[skip ci]` в последнем коммите (проверки не запускаются, идущий `smoke` не отменяется — проверено, `docs/technical-notes.md`); `smoke` на пачке — вручную (`workflow_dispatch`, `ref` — полный хеш); сборку ветки для ссылок (`preview.yml`) после такого push — тоже вручную. «Не пушить во время `smoke`» — только для push без `[skip ci]`.
    - **Плавающие проверки:** первое падение — один перезапуск; повторное — короткий разбор (связано ли с новым кодом); не связано — запись в список плавающих (`docs/technical-notes.md`) и дальше; список чинить пачкой раз в 2–3 дня.
    - **Без «да» владельца:** исправления по принятым спискам; починка проверок; ускорение и экономия памяти без видимых изменений; переделка кода без изменения поведения; замеры и серии ботов (числа — через `--cfg`, `config.ts` не трогать); документы. **«Да» нужно:** числа баланса в `src/config.ts`; видимые изменения графики и интерфейса; тексты игры; новые механики и контент; слияние в `main`.
    - **Отчёт:** первая строка — «Решения не нужны» или «Нужно ваше решение: N вопросов» (с вариантами и рекомендацией); затем таблица «Что сделано / Проверка / Результат / Что нужно от меня». Пока ждёшь ответа — работать по задачам без решений.
    - **Ночь:** перед паузой ставить долгие задачи (серии, полные замеры).

## Команды
| Команда | Что делает |
|---|---|
| `PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1 npm install` | установить зависимости (в облаке) |
| `npm run dev` | игра для разработки: http://localhost:5173 |
| `npm run build` / `npm run build:qa` | проверка типов + игровая сборка `dist/` (режима `?qa` нет; уйдёт на Яндекс) / тестовая `dist-qa/` (с `?qa`) |
| `npm run typecheck` | только проверка типов (быстро) |
| `node qa/perf.mjs` | замер скорости в стресс-сценарии; **на сервере идёт сам (`perf.yml`, сравнение с `.github/perf-base`), локально не запускать** |
| `npm run qa -- --tag=<имя>` | обе сборки + `smoke`; **на сервере идёт сама, локально не запускать** |

`node qa/ladder-sets.mjs --attempts=1` (набор улучшений 1-й партии по модели очков ДНК; чистый расчёт, но нужен `npm install`) — можно запускать локально.

Структура папок и устройство кода — `docs/technical-notes.md`. Все числа баланса — `src/config.ts`. Счётчик кадров `?fps` — во всех сборках. Режим `?qa` (`/?qa&speed=4&cfg=раздел.параметр:число&lang=en&level=5&noplaque&canvas&stress`) — только `npm run dev` и тестовая сборка; `?level=N` работает и в игровой.
Пример: `?qa&cfg=economy.rewardCurve.2.1:0.3` (точка кривой наград).
