# Таблетки против бактерий (Pills vs Bacteria)

Казуальная HTML5-игра для публикации на **Яндекс Играх**. Владелец проекта — юрист, не программист: технические решения принимаются самостоятельно и коротко объясняются простыми словами (по-русски, на «вы»), без жаргона. Формат отчёта — правило 10 (первая строка «Решения не нужны» или «Нужно ваше решение: N вопросов», затем таблица «Что сделано / Проверка / Результат / Что нужно от меня»).

**Последняя передача:** `docs/handoff-2026-10-25.md` (ветки и открытые PR, запуски Actions, статус заданий, вопросы владельцу, следующий шаг). Читать: этот файл → передача → `docs/decisions.md` (последние записи) → при необходимости `docs/status-log.md`, `docs/td-plan.md`. Прежняя редакция этого файла с подробными решениями и целями — `docs/claude-md-archive-2026-10-25.md`.

## Главные решения (журнал — `docs/decisions.md`; сообщения владельца — `docs/owner-messages-<дата>.md`)
- **Жанр tower defense** (решение владельца, сессия перехода): башни стоят в клетках и стреляют сами, бактерии идут по кривым дорожкам со слияниями и разветвлениями (сеть «корни») от правого края к организму слева; игрок ставит, сливает и улучшает башни; деньги — за убитых бактерий; у башен разные способы стрельбы. Старая игра (падающие бактерии, тап-выстрел) — в истории, коммит `3b913a3`. **20 уровней** (решение 26 октября 2026, сообщение 1, п. 5; прежние «10 уровней» отменены), главы по органам, по два уровня на карту (глава 1 «Горло и нос»: уровень 2 — отдельная карта «Нос», исключение только для главы 1); `levelMul` 1,0 на всех уровнях (`docs/levels-plan-2026-10-25.md`; в `src/config.ts` — пакетом колец и пределов); уровень — 50 волн с боссом в конце, затем по желанию бесконечный режим (18 октября 2026, вечер).
- **Концепция:** уровень не проходится с первой попытки: игрок проигрывает, копит ДНК, покупает улучшения (экран «Улучшения»), потом проходит; слияние до VIII, опыт и древо не дают перекачаться сразу; ступени-стены, мини-боссы и босс на каждом уровне (`docs/redesign-2026-10-19.md`). Предел слияния и ранга опыта растёт с уровнем игры: на уровне 1 — до V и ★4, максимум (VIII, ★8) — не раньше середины игры; недоступное — серое, без текста. Древо: центр «Сильное вещество»; кольца открываются победами на уровнях (внутреннее — сразу, кольцо 2 — после победы на уровне 2; таблица п. 4 `docs/levels-plan-2026-10-25.md`), в кольцах узлы силы, узлы башен — только ценой; закрытое кольцо серое; вид экрана — на решении владельца (радиальный макет принят 26 октября 2026, затем «сделать интереснее: как в PoE или как атом»). Проверка каждого уровня: сильнейшая стратегия с древом после победы на прошлом уровне и N его повторов (ДНК повторов ×0,3) не проходит новый уровень с первой попытки. Башни открываются только за ДНК в древе, стартовая — Таблетка. **В бою текстовых подсказок нет**, кроме ответа на неудачное действие (нет монет, здесь нельзя) и строки проигрыша после попытки. **Альманах — только встреченное, без чисел** (бактерия и босс — с первого выхода на поле, башня — когда куплена; закрытая запись — «Ещё не встречалось»). Пауза затемняет поле, строить в паузе нельзя; перезапуск после конца уровня только кнопкой «Заново». (Решения 25 октября 2026, сообщение 5.)
- **Сложность.** Ориентир — сильнейшая стратегия ботов: сейчас образец рецензента (`--strategy=review`), эксперт (`expert`, `core:syrup+syringe:late25x2`) подтягивается к нему общими правилами. **Цель уровня 1** (решение 25 октября 2026, сообщение 1, п. 8): на 6 дорожках (`k` 6, `k_total` 12) медиана первой победы сильнейшей стратегии 8–10, ни одной дорожки раньше 7-й и позже 12-й, гибель сдвигается хотя бы на одну стену не реже раза в 3 попытки. **Устарели** и не действуют: цели `docs/difficulty-plan.md` («15–22-я волна, победа не позже 4-й попытки»), «эксперт побеждает на 8–10-й попытке» (заменена 25 октября 2026), `docs/balance-rework-plan-2026-10-18.md`. **Цель уровней 2–20** (решение 26 октября 2026, сообщение 1, п. 5.4): сильнейшая стратегия с древом после победы на прошлом уровне и N = 3 повторами (контроль N = 5) — медиана первой победы 3–5 попыток, ни одной дорожки с первой попытки и позже 7-й; замер уровней 2+ — эксперт с перебором ключевых клеток (проверка на уровне 1). Ограниченные стратегии (одна башня, пара) за 20 попыток не побеждают (правило 4.3 документа дизайна).
- **Мета-прогрессия** (документ дизайна, раздел 6): сохранение — `pvb.meta5`, с нуля; числа уровня 1 — в `src/config.ts`. Подробности — `docs/decisions.md`, `docs/redesign-2026-10-19.md`.
- **Слияние до VIII, опыт и ранги** — `docs/tower-levels-xp-plan-2026-10-24.md`; код в ветке `claude/pvb-levels8-xp`, в `main` не слит.
- **Графика:** стиль пилота (вариант Б) на всех видах; **глаз нет ни у таблеток, ни у бактерий** (решение 25 октября 2026, сообщение 3; прежнее решение о глазах отменено); у всего нового свой вид (рисунки уровней V–VIII, ранги, слияния — поручение 25 октября 2026).
- Режим проверки: без `&levelwaves` — прежний тестовый уровень (карта «корни»); с `&levelwaves` — настоящие уровни; `&towers=all` — все башни без древа, `&wave=N` — старт с волны N, `&ready=2` — открыть уровень 2 (в игровой сборке открыт только 1).
- Боты и проверки — только GitHub Actions; сборки веток — по своим ссылкам. Обойма отвергнута навсегда. Phaser 3.90 (не обновлять до 4), TypeScript, Vite; графика и звуки — кодом, без внешних файлов; тексты — русский и английский.

## Правила проекта (обязательно)
1. **План → одобрение → код.** Крупные решения сначала согласуются с владельцем (что делается без «да» и что требует «да» — правило 10).
2. **Баланс — только в `src/config.ts`** (комментарии на русском, с единицами измерения). Башни и улучшения — строками таблиц (данные).
3. **Тексты — на русском и английском** в `src/i18n.ts` (без перевода проект не соберётся); строк-надписей в коде сцен нет.
4. **Графика рисуется кодом**, без внешних картинок.
5. **Конец каждого этапа:** сборка → проверки на GitHub → снимки → команда, по которой владелец сам поиграет; затем коммит и push в рабочую ветку. **Pull request — только по просьбе владельца, слияние в `main` — только по названному им PR** (25 октября 2026; «Слей все PR» — все открытые, нет открытых — сказать об этом). После слияния PR рабочую ветку начинать заново от `main`; если на ветке идут замеры по её коммитам или есть не слитые коммиты — слить `main` в ветку, историю не переписывать. Полный текст — `docs/project-rules-details.md`.
6. Владелец следит из приложения Claude: файлы для него класть внутри проекта (снимки прогонов — `qa/screenshots/`, она в `.gitignore`; снимки в репозитории не хранятся).
7. **Боты и проверки — только через GitHub Actions** (`balance.yml`, `ladder.yml`, `checks.yml`, `perf.yml`; `docs/bot-prompts.md`). Запуск: `actions_run_trigger` (`ref` — ветка; `inputs.ref` — полный хеш коммита) либо файл запроса + push. **Локально `npm run qa`, `qa/smoke.mjs`, `qa/bot.mjs` не запускать** (слабая машина); локально — `npm run typecheck`, `node --check`, сборки. Число партий не экономить. Push без `[skip ci]` запускает `smoke` (кроме правок только в `docs/`, `*.md`) и отменяет идущий. Лестница: не больше двух серий сразу (6 задач на серию, лимит мест 14, «Сторож мест» останавливает лишнюю), все серии одного сравнения — на одном коммите; чтение итога — `docs/project-rules-details.md`, `docs/technical-notes.md`.
8. **Производительность:** кадры в секунду из GitHub Actions не считать результатом. В облаке — только «до/после» (`perf.yml`, одна машина) и время расчётов на кадр; **итог — замер владельца по `?fps` на компьютере, iPhone и iPad** (`docs/performance.md`).
9. **Секреты:** ключи Яндекса и любые пароли, токены, личные данные — только в GitHub Secrets, никогда в коде, `src/config.ts`, `docs/`, примерах запросов и сообщениях коммитов; проверка на секреты — перед публикацией (этап 9) и перед каждым слиянием в `main`. **Почта в коммитах:** `335224071+Aurinox-eng@users.noreply.github.com` (в начале работы проверить `git config user.email`); предупреждение стоп-хука «Unverified» не выполнять, историю не переписывать. Подробности — `docs/project-rules-details.md`.
10. **Темп работы** (полный текст — `docs/project-rules-details.md`):
    - **Пачки:** код — отдельными коммитами; `smoke` — один на пачку; упала группа — искать коммит по названию группы.
    - **Отправка без ожидания:** push с `[skip ci]` в последнем коммите (идущий `smoke` не отменяется); `smoke` на пачке — вручную (`checks.yml`, `ref` — полный хеш, `scope` — `full` или список сценариев); сборку ветки (`preview.yml`) — тоже вручную.
    - **Плавающие проверки:** первое падение — один перезапуск; повторное — короткий разбор; не связано с кодом — запись в список плавающих (`docs/technical-notes.md`); список чинить пачкой раз в 2–3 дня.
    - **Без «да» владельца:** исправления по принятым спискам; починка проверок; ускорение без видимых изменений; переделка кода без изменения поведения; замеры и серии ботов (числа — через `--cfg`); документы. **«Да» нужно:** числа баланса в `src/config.ts`; видимые изменения графики и интерфейса (рисунки — сначала лист образцов `?qa&artsheet` и снимки 1280×720 и 844×390 в плотной поздней сцене, после «да» остальное; код рисунков — в отдельной ветке; анимации — вращением готовой картинки, без перерисовки каждый кадр; `perf.yml` до и после); тексты игры; новые механики и контент; слияние в `main`.
    - **Отчёт:** первая строка — «Решения не нужны» или «Нужно ваше решение: N вопросов» (с вариантами и рекомендацией); затем таблица. Пока ждёшь ответа — работать по задачам без решений.
    - **Ночь:** перед паузой ставить долгие задачи (серии, полные замеры).
11. **Передача работы:** когда контекст подходит к концу, новых задач не начинать. `CLAUDE.md` — коротко и только постоянное; текущее состояние, историю замеров и устаревшее — в `docs/`. Сообщения владельца, которых нет в репозитории, — дословно в `docs/owner-messages-<дата>.md` (у каждого дата; большие приложения — отдельным файлом). Решения владельца — в `docs/decisions.md` с датой; отмену писать прямо, прежнее помечать «отменено» со ссылкой на новое; отменённые цели сложности — устаревшими. Передача — `docs/handoff-<дата>.md`: ветки (что лежит, что слито, открытые PR), запуски Actions (номера, когда итог, что делать), статус заданий владельца по пунктам, вопросы владельцу с вариантами и рекомендацией, следующий шаг. Неотправленного кода не оставлять: последний push с `[skip ci]`, проверить, что идущий `smoke` не отменился, результат записать в передачу. Итог — одно сообщение владельцу: рабочая ветка, путь к передаче, что идёт в Actions и когда итог, весь ли код отправлен, вопросы.
12. **Цитаты и решения:** в кавычках — только дословный текст; решение владельца по названным пунктам применяется только к ним, смежное — перечнем с рекомендацией и после «да»; **бот и числа баланса в одном замере не менять вместе** — сначала бот, потом числа; правка бота (правила `fx`) — каждая своей лестницей на одном коммите; если после правок цель не достигнута — остановиться и прислать сводку (что перенесено, что нет и почему), дальше решает владелец.

## Команды
| Команда | Что делает |
|---|---|
| `PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1 npm install` | установить зависимости (в облаке) |
| `npm run dev` | игра для разработки: http://localhost:5173 |
| `npm run build` / `npm run build:qa` | проверка типов + игровая сборка `dist/` (режима `?qa` нет; уйдёт на Яндекс) / тестовая `dist-qa/` (с `?qa`) |
| `npm run typecheck` | только проверка типов (быстро) |

`node qa/ladder-sets.mjs --attempts=1` (набор улучшений 1-й партии; чистый расчёт) — можно локально. `qa/perf.mjs`, `npm run qa` — только на сервере. Структура папок и устройство кода — `docs/technical-notes.md`. Все числа баланса — `src/config.ts`. Счётчик кадров `?fps` — во всех сборках. Режим `?qa` (`/?qa&speed=4&cfg=раздел.параметр:число&lang=en&level=5&noplaque&canvas&stress&artsheet`) — только `npm run dev` и тестовая сборка.
