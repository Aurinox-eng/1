## Принятые решения (кратко; правила — `docs/td-rules.md`, журнал — `docs/decisions.md`)
- **Переход на tower defense** (владелец): поле **горизонтальное 1280×720**, красная линия («организм») **слева**, бактерии идут от
  правого края к организму по **кривым дорожкам** со слияниями и разветвлениями (сеть «корни», случайный выбор пути) на **большой
  карте 18×14 клеток с камерой** (сдвиг пальцем, масштаб щипком и колесом мыши). Башни ставятся при любом приближении.
- Башни стоят в клетках, сами стреляют; **у башен разные способы стрельбы** (по радиусу, по площади, одна цель, вперёд/назад…);
  игрок только ставит и улучшает башни. Деньги — за убитых бактерий. Уровни с победой. Все пять типов бактерий остаются
  (палочка — рывки; делящаяся — два кокка при гибели; бронированная; спора — глушит башню). В итоге ≈10 башен; глубина —
  улучшения в партии + большое постоянное дерево за «очки ДНК» (прежде «антитела»; проект в `docs/upgrades.md`, без кода, ждать «ок»; этап 6).
- **Боты и проверки — запускает ВЛАДЕЛЕЦ в отдельных чатах, не агент** (решение владельца: «если нужны боты, пиши мне промпт, я запущу в отдельных
  окнах и пришлю результаты»; так я не загружен прогонами). Готовые шаблоны промптов — `docs/bot-prompts.md`. Владельцу в конце этапа —
  **одна итоговая таблица** («Что сделано / Проверка / Результат / Что нужно от вас»), без логов и чисел бота.
- Обойма отвергнута навсегда. Phaser 3.90 (не обновлять до 4), TypeScript, Vite; графика и звуки — кодом, без внешних файлов.

## Команды
| Команда | Что делает |
|---|---|
| `npm install` | установить зависимости (в облаке: `PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1 npm install`) |
| `npm run dev` | игра для разработки: http://localhost:5173 |
| `npm run build` | проверка типов + ИГРОВАЯ сборка в `dist/` (уйдёт на Яндекс; режима `?qa` в ней нет) |
| `npm run build:qa` | ТЕСТОВАЯ сборка в `dist-qa/` (с режимом `?qa`) |
| `npm run preview` | посмотреть собранную игровую версию |
| `npm run typecheck` | только проверка типов (быстро, у главного агента) |
| `npm run qa -- --tag=<имя>` | обе сборки + проверка в браузере, скриншоты в `qa/screenshots/<имя>/`; весь набор ≈ 15 мин; `--only=<сценарий>`. **Запускает `qa-tester`**; `src` во время прогона не править |

Структура папок и устройство кода — `docs/technical-notes.md`. Все числа баланса — только `src/config.ts`.
Бот-замерщик баланса — `qa/bot.mjs` (запуск и профили — `docs/technical-notes.md`); боты — только через субагентов, `--speed` не выше 2, `--canvas`.

## Правила проекта (обязательно)
1. **План → одобрение → код.** Крупные решения сначала согласуются с владельцем.
2. **Баланс — только в `src/config.ts`** (скорости, частоты, очки, паузы), комментарии на русском, с единицами измерения.
   Башни и улучшения — строками таблиц (данные), не разбросаны по коду.
3. **Тексты — на русском и английском** в `src/i18n.ts` (без перевода проект не соберётся); строк-надписей в коде сцен нет.
4. **Графика рисуется кодом**, без внешних картинок.
5. **Конец каждого этапа:** сборка → прогон `qa-tester` → скриншоты → команда, по которой владелец сам поиграет; затем коммит
   и push в рабочую ветку `claude/serene-rubin-x3t2gu`. **Pull request — только по просьбе владельца.**
6. Владелец следит из приложения Claude: файлы для него класть внутри проекта (скриншоты прогонов — в `qa/screenshots/`, она в `.gitignore`; в репозитории остаются только 2–3 итоговых снимка этапа в `docs/screenshots/`).
7. **Боты и проверки (`npm run qa`, `qa/smoke.mjs`, `qa/bot.mjs`) агент в этой сессии НЕ запускает — ни сам, ни через субагентов.** Если они нужны,
   он пишет владельцу готовый промпт (шаблоны — `docs/bot-prompts.md`; перед этим всё закоммичено и запушено, в промпте — ветка и коммит) и ждёт
   блоки результатов. **Промпт — целиком для копирования, с указанием модели и уровня усилия (low/medium/high/xhigh/max); число партий не экономить (решение владельца).** Владельцу — только итоговая таблица. Быстрая `npm run typecheck` при написании кода остаётся у главного агента.

## Субагенты (`.claude/agents/`)
- **game-designer** — проектирует и настраивает баланс (башни, бактерии, волны, экономика, улучшения), правит только
  `src/config.ts` и `docs/`; **по присланным владельцем результатам бота** подбирает числа (сам бота не запускает).
- **qa-tester** — запускает игру в браузере (Playwright), проверяет консоль, делает скриншоты, код не правит. Работает в отдельных
  чатах владельца (по промптам из `docs/bot-prompts.md`), в этой сессии не запускается.
- Определения агентов подхватываются только при старте сессии: в текущей сессии новые инструкции давать в самом промпте.

## Публикация и режим проверки
- **GitHub Pages:** при каждом обновлении `main` workflow `pages.yml` собирает `npm run build` и выкладывает `dist/` на
  https://aurinox-eng.github.io/1/ (+ `version.txt`). Ветка `claude/...` не публикуется. На Яндекс Игры — zip-архивом (этап 9).
- **Режим `?qa`** (`/?qa&speed=4&cfg=раздел.параметр:число&lang=en`) открывает состояние игры для тестов. Работает только при
  `npm run dev` и в тестовой сборке, в игровую не попадает (проверка в `qa/smoke.mjs`). Подробности — `docs/technical-notes.md`.
