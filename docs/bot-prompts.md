# Боты и проверки: как запускать (GitHub Actions)

**С круга 15 боты и проверки идут на GitHub, а не в отдельных чатах** (решение владельца: экономия токенов). Отдельные чаты, промпты «для копирования» и выбор модели больше не нужны.
Шаблоны 1–14 удалены 16.10.2026; последний коммит, где они есть, — `e3b5362`.

## Замер ботом: `balance.yml` («Замер баланса (боты)»)
Каждый профиль, каждый набор исключённых башен (`--exclude`) и каждая «доля» партий — отдельная параллельная задача (матрица), бот идёт с `--canvas`. Последняя задача «Итоговая таблица» складывает результаты всех задач.

**Поля запуска:**
| Поле | Что значит | По умолчанию |
|---|---|---|
| `ref` | ветка или коммит | пусто — та ветка, с которой запущено (любая `claude/…`) |
| `profiles` | стратегии эксперта через запятую (профиль один — `expert`, решение владельца 19 октября 2026): `expert` (обычная), `zone` (Таблетки и один Сироп у последней развилки), `solo:X` (одна башня, без Сиропа), `pair:a+b`, `focus:a+b`, `core:a+b` (эксперт без ограничения башен: ядро a + b, Сироп и Шипучка против стен, остальные открытые башни) | `expert` |
| `muts` | наборы мутаций через «\|»: `-` — по умолчанию (`DEFAULT_MUT` в `qa/bot.mjs`), `alt` — на каждом пороге другой вариант, либо `башня:мутация,мутация;…` | `-` |
| `runs` | партий на каждый профиль и набор исключений (партия на 30 волн — 15–45 минут) | 5 |
| `shards` | на сколько параллельных задач разнести партии каждой пары «профиль + набор»: 1 — партии идут подряд в одной задаче; равно `runs` — быстрее всего (по партии в задаче) | 1 |
| `excludes` | наборы исключённых башен через «;»: `-;syrup` — без исключений и без Сиропа; `fizz,syringe` — без двух башен; `-` — не исключать | `-` |
| `lamps` | «Лампы против скрытных» (`--lamps`), только стратегия `expert`, не сочетается с `solos`. `1` — с 8-й волны Лампа идёт раньше Ампулы и Антибиотика, по одной на 2 Таблетки (потолок 3); `veteran` — «опытный»: Лампы с (волна выхода скрытных − 3)-й волны; `first` — «первая встреча»: Лампы после выхода первой скрытной. Несколько вариантов через «;» (`-` — без Ламп), например `veteran;first`. В таблице — колонка «Жизней от скрытных» | пусто |
| `solos` | варианты «одна башня» (`--solo`) через «;»: `-;fizz` — обычная игра и только Шипучка + 1 Сироп; башни `pill`, `fizz`, `syringe`, `ampule`, `antibiotic`, `lamp`, `vitamin`, `frost`, `patch` (три последние — «башня + 1 Сироп + Таблетки»; `pill` — база для сравнения); только стратегия `expert`; узел башни бот открывает сам. В запросе-файле ключ `solos` | `-` |
| `cfg` | подмена чисел, например `economy.rewardMul:0.85,waves.hpGrowthPerWave:0.06`; несколько вариантов — через «;» (`-;towers.fizz.blastFullTargets:999`: «-» без подмены): каждый вариант идёт отдельными задачами в одном прогоне — так сравнивают «до/после» | пусто |
| `level` | уровень 1–10 (какие башни открыты) | 1 |
| `speed` | ускорение игры для бота; для итоговых чисел — 2 | 2 |
| `campaign` | серии партий (этап 6а): `0` — обычный замер; `N` — каждая из `runs` серий играет до N партий подряд одним профилем с очками ДНК и улучшениями (бот начисляет очки и покупает улучшения сам) и заканчивается первой победой; итог — номер партии первой победы | 0 |

**Замер «одна башня против смешанного набора»** (`docs/fizz-solo-plan.md`). Улучшения вне партии для одиночной башни считаются так: `node qa/ladder-sets.mjs --solo=fizz --levels=5,10 --attempts=1` (те же очки ДНК, но сначала ветка этой башни); для смешанного набора — `node qa/ladder-sets.mjs --levels=5,10 --attempts=1`. Строку `meta` каждого набора вставляют в поле `meta`; смешанный набор и одиночные башни идут **отдельными запросами** (у запроса одно значение `meta`). В итоговой таблице есть столбец «Медиана волны» (победа считается как все волны уровня); вариант подписан «одна башня: …». Цель замера: смешанный набор гибнет около 22–26-й волны (если нет — правится `latePerWave` уровня подменой `--cfg levels.specs.<N−1>.growth.latePerWave:<число>`), одиночная башня — минимум на 3 волны раньше и без побед.

**Места на сервере (решение владельца 15 октября 2026).** На аккаунте GitHub одновременно идёт не больше 20 задач на всё (проверки `smoke` — 10 задач, лестницы, замеры, публикация). Длинные серии (лестница `ladder.yml` и замер `balance.yml`) вместе занимают не больше 14 мест, для `smoke` остаётся не меньше 6. Это проверяет сам запуск: поле `max_parallel` лестницы (по умолчанию 7, больше 7 не принимается) и `max-parallel: 7` у замера ограничивают серию, а шаг «Сторож мест» (`.github/scripts/slots-guard.mjs`) в задаче «Список …» считает задачи других идущих серий и при сумме больше 14 останавливает запуск с сообщением. Уже идущие серии не отменяются. Скорость бота и лестницы — до 5 (5 — как кнопка ×5 в игре).

**Как запустить:**
1. **Кнопкой** (владелец): GitHub → вкладка **Actions** → слева «Замер баланса (боты)» → справа **Run workflow** → поля → зелёная кнопка **Run workflow**. Кнопка появляется, когда файл `.github/workflows/balance.yml` лежит в `main`.
2. **Файлом запроса** (агент, без кнопки): изменить `.github/balance-request.json` (те же поля в нижнем регистре; число можно писать числом) и сделать push в рабочую ветку — запустится замер по этому файлу.
3. **Через API** (агент): инструмент `actions_run_trigger` (`run_workflow`, `workflow_id: balance.yml`, `ref` — рабочая ветка, `inputs` — поля как строки). Работает для ветки, на которой workflow уже запускался.

**Где итог:** страница прогона → внизу **Summary** — «Итог замера бота» (таблица в формате бота: профиль, партий, побед, потеряно жизней, волна гибели, башни, монеты в конце, время партии; под ней — строки партий, постройки по видам, волны потери жизней, раздел «Проблемы»). Тот же текст — в логе задачи «Итоговая таблица» (агент читает его через `get_job_logs`). Сырые JSON — внизу страницы прогона, **Artifacts**: `bot-<тег>` по задачам и `bot-results-all` одним набором вместе с `summary.md`.
Расход: задача занимает одну машину на всё время партии (≈ 15–45 минут на партию при `speed` 2 + 1–2 минуты на установку); число задач = профили × наборы × доли.

## Проверки `smoke`: `checks.yml` («Проверки (smoke)»)
Идут сами на каждый push в рабочую ветку (правки только в `docs/` и `*.md` их не запускают). Сценарии разложены по группам из `.github/smoke-groups.json` (на 28 октября 2026 — 10 групп), группы идут параллельно, внутри группы сценарии — по одному (находка аудита MASTER-0118). Упала проверка — задача красная, GitHub присылает письмо о неудачном запуске
(включить: GitHub → Settings → Notifications → Actions → «Send notifications for failed workflows only», галочка Email). Снимки упавших задач — во вложениях прогона (`smoke-shots-…`, 7 дней). Вручную: Actions → «Проверки (smoke)» → Run workflow.

## Лестница: `ladder.yml` («Лестница (боты по уровням)»)
Игрок-бот проходит уровни подряд: на каждом играет до первой победы (не больше `k` партий), очки ДНК и покупки переходят на следующий уровень через вложение `ladder-state-L<уровень>-lane<дорожка>` (30 дней). Каждая дорожка — отдельная задача. Предел одной задачи — 5 ч 50 мин, поэтому длинный уровень играется в несколько задач (`k_total`). Итог — задача «Итоговая таблица», сырые JSON — вложения `ladder-res-L<уровень>-lane<дорожка>` (`qa/bot-results/ladder-L<N>-lane<K>.json`).

**Запуск.** Кнопкой (Actions → «Лестница (боты по уровням)» → Run workflow), через API (`workflow_dispatch`, `ref` — рабочая ветка, поля как строки), либо файлом `.github/ladder-request.json` (ключи в нижнем регистре) и push в рабочую ветку. Места: серии вместе не больше 14 дорожек из 20 (`max_parallel` не выше 7, сторож мест `slots-guard.mjs`).

| Поле | Что значит | По умолчанию |
|---|---|---|
| `ref` | ветка или коммит | пусто — ветка запуска |
| `profile` | стратегия эксперта: `expert`, `zone`, `solo:X` (одна башня, без Сиропа), `pair:a+b`, `focus:a+b`, `core:a+b` (эксперт без ограничения башен: ядро a + b, Сироп и Шипучка против стен, остальные открытые башни) | `expert` |
| `mut` | набор мутаций: пусто — по умолчанию, `alt` или `башня:мутация,мутация;…`; правила бота — записью `fx:…` через «;» (например `pill:pillRapid,pillHunter;fx:scout`) | пусто |
| `lanes` | число дорожек (независимых игроков), 1–10 | 6 |
| `k` | партий на уровне за одну задачу | 8 |
| `k_total` | всего партий на уровне до «застряла»: больше `k` — уровень играется несколькими задачами подряд по `k` партий с передачей состояния | пусто (= `k`) |
| `budget_sec` | бюджет реального времени задачи при `k_total` > `k`: новая партия не начинается, если не успеет закончиться до него | 19800 (5 ч 30 мин) |
| `to_level` | до какого уровня идти (1–10) | 10 |
| `from_level` | **с какого уровня начинать (1–10, не больше `to_level`)**; больше 1 — нужен `state_run` | 1 |
| `state_run` | **номер прогона (run id), из вложений которого берётся состояние дорожек `ladder-state-L<from_level − 1>-lane<N>`** (дорожки и профиль должны совпадать с теми, что были в том прогоне; вложения живут 30 дней); при `from_level` = 1 не задаётся | пусто |
| `speed` | ускорение игры для бота; для итоговых чисел — 2 | 2 |
| `cfg` | подмена чисел `--cfg`, например `levels.specs.1.growth.latePerWave:1.15` | пусто |
| `farm` | контроль фарма очков ДНК: после первой победы на уровне одна партия на пройденном (1 — да) | 0 |
| `max_real_sec` | потолок реального времени одной партии бота, с | 7200 |
| `max_parallel` | сколько дорожек серии идёт одновременно | 7 |

**Старт с середины (`from_level`, `state_run`).** Экономит часы: например, серия для уровня 2 берёт состояние после уровня 1 из готового прогона, а не проходит уровень 1 заново. Пример: профиль `expert`, 2 дорожки, `from_level` 2, `state_run` `38771135100`, `to_level` 2. Уровни ниже `from_level` в задаче пропускаются. Если вложения нет или оно просрочено, задача уровня падает на шаге «Состояние дорожки из другого прогона».

**Эксперт с разведкой ключевых клеток (`fx:scout`; вариант А, `docs/levels-plan-2026-10-25.md`, раздел 7; решение владельца 4 ноября 2026, сообщение 2, п. 1).** Новых полей нет: правило включается записью `fx:scout` в поле `mut`. Поля: `profile` `core:syrup+syringe:late25x2`, `mut` `pill:pillRapid,pillHunter;fx:scout`, `lanes` 6, `k` 6, `k_total` 12 (разведке нужен бюджет задачи — он действует только при `k_total` больше `k`; `budget_sec` по умолчанию 19800), `to_level` 1 — проверка на уровне 1 рядом с образцом (`review`, медиана 8); для уровней 2–4 — `from_level`/`state_run`/`to_level` как обычно. Что делает бот: один раз на уровень, перед первой попыткой, в которой открыты Шприц и Сироп (на уровне 1 — после их покупки за ДНК, обычно со 2-й попытки), он играет разведочные партии до 25-й волны с древом этой попытки: базовую (обычный выбор клеток), по одной на каждую из 4 линий луча Шприца (лучшие по числу пересечений с дорожкой, как `fx:beam`) и на каждое из 4 мест лужи Сиропа (лучшие по охвату дорожки с лучом базового Шприца). Лучшие клетки — у каждой башни отдельно: больше жизней после 25-й волны, затем дальше волна, затем больше заработано монет; при равенстве остаётся обычный выбор. Во всех попытках уровня первый Шприц (с направлением луча) и первый Сироп ставятся в выбранные клетки, при слиянии итог остаётся в них; остальные башни — обычным выбором. Разведка не считается попыткой и не меняет ДНК и древо; итог — объект `scout` в записи уровня дорожки (`ladder.lanes[].perLevel[].scout` в `ladder-res-…`: кандидаты с оценкой бота и результатами, выбор, время) и строка «разведка клеток: …» в логе. Время — до 9 коротких партий на дорожку и уровень (≈ 1–2,5 ч); не помещается в бюджет — разведка короче (меньше кандидатов, строка «разведка короче»).

**Дорожка `expert` до победы или 10 попыток.** Задавать `k` 5 и `k_total` 10: первая задача играет до 5 партий, вторая продолжает с сохранённого состояния; одна задача на 10 партий обрывается лимитом 5 ч 50 мин на 6–8-й партии, и состояние уровня теряется.


### Образец на картах уровней 2–4 и повторы пройденного уровня (5 ноября 2026)

- Образец (`--strategy=review`): на «Горле» — клетки рецензента (`REVIEW_GROUPS`, уровень 1 — без изменений); на остальных картах клетки и луч Шприца (`aim`) — правилом по графу карты (`qa/graph-layout.mjs`; решение владельца 6 ноября 2026, сообщение 1, п. 1.1): оборона у спуска каждого канала, Сироп в зоне своей обороны, Шипучки не ближе 150 px к Таблеткам, луч с наибольшей длиной путей под ним. Группы, очередь постройки и мутации — те же. На уровнях 2+ образец покупает и строит новые башни (Ампула; решение 8 ноября 2026, сообщение 1, п. 3).
- **Снимки клеток бота** (решение владельца 8 ноября 2026, сообщение 1, п. 4): в облаке — Actions → «Клетки бота» (`bot-cells.yml`) → Run workflow (поле `levels` — уровни через запятую, `ref` — ветка или хеш); снимки и текст «какой путь закрывает группа» — в артефакте прогона `bot-cells` и на странице итога прогона. Запустить кнопкой можно, когда файл `bot-cells.yml` есть в `main`. На своей машине: `npm run build:qa`, затем `node qa/bot-cells.mjs --levels=2,3,4` (снимки — `qa/screenshots/bot-cells-L<уровень>.png` и `.txt`).
- `--mut ...;replays:N` — повторы пройденного уровня (N раз) играются в начале следующего уровня, до первой попытки (ДНК — по правилу повтора, после каждого — покупки). Цель уровней 2–30: N = 3, контроль N = 5. Лестница: `profile` `review`, `mut` `fx:v;replays:3`, `to_level` 2, `farm` 0.
