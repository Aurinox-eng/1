# Боты и проверки: как запускать (GitHub Actions)

**С круга 15 боты и проверки идут на GitHub, а не в отдельных чатах** (решение владельца: экономия токенов). Отдельные чаты, промпты «для копирования» и выбор модели больше не нужны.
Шаблоны промптов ниже (1–14) — архив: из них полезны команды и описания сценариев и профилей.

## Замер ботом: `balance.yml` («Замер баланса (боты)»)
Каждый профиль, каждый набор исключённых башен (`--exclude`) и каждая «доля» партий — отдельная параллельная задача (матрица), бот идёт с `--canvas`. Последняя задача «Итоговая таблица» складывает результаты всех задач.

**Поля запуска:**
| Поле | Что значит | По умолчанию |
|---|---|---|
| `ref` | ветка или коммит | `claude/serene-rubin-x3t2gu` |
| `profiles` | профили через запятую: `novice`, `average`, `strong`, `expert` (или `all`) | все четыре |
| `runs` | партий на каждый профиль и набор исключений (партия на 30 волн — 15–45 минут) | 5 |
| `shards` | на сколько параллельных задач разнести партии каждой пары «профиль + набор»: 1 — партии идут подряд в одной задаче; равно `runs` — быстрее всего (по партии в задаче) | 1 |
| `excludes` | наборы исключённых башен через «;»: `-;syrup` — без исключений и без Сиропа; `fizz,syringe` — без двух башен; `-` — не исключать | `-` |
| `cfg` | подмена чисел, например `economy.rewardMul:0.85,waves.hpGrowthPerWave:0.06` | пусто |
| `level` | уровень 1–10 (какие башни открыты) | 1 |
| `speed` | ускорение игры для бота; для итоговых чисел — 2 | 2 |

**Как запустить:**
1. **Кнопкой** (владелец): GitHub → вкладка **Actions** → слева «Замер баланса (боты)» → справа **Run workflow** → поля → зелёная кнопка **Run workflow**. Кнопка появляется, когда файл `.github/workflows/balance.yml` лежит в `main`.
2. **Файлом запроса** (агент, без кнопки): изменить `.github/balance-request.json` (те же поля в нижнем регистре; число можно писать числом) и сделать push в рабочую ветку — запустится замер по этому файлу.
3. **Через API** (агент): инструмент `actions_run_trigger` (`run_workflow`, `workflow_id: balance.yml`, `ref` — рабочая ветка, `inputs` — поля как строки). Работает для ветки, на которой workflow уже запускался.

**Где итог:** страница прогона → внизу **Summary** — «Итог замера бота» (таблица в формате бота: профиль, партий, побед, потеряно жизней, волна гибели, башни, монеты в конце, время партии; под ней — строки партий, постройки по видам, волны потери жизней, раздел «Проблемы»). Тот же текст — в логе задачи «Итоговая таблица» (агент читает его через `get_job_logs`). Сырые JSON — внизу страницы прогона, **Artifacts**: `bot-<тег>` по задачам и `bot-results-all` одним набором вместе с `summary.md`.
Расход: задача занимает одну машину на всё время партии (≈ 15–45 минут на партию при `speed` 2 + 1–2 минуты на установку); число задач = профили × наборы × доли.

## Проверки `smoke`: `checks.yml` («Проверки (smoke)»)
Идут сами на каждый push в рабочую ветку (правки только в `docs/` и `*.md` их не запускают). Все 33 сценария разложены по 7 параллельным задачам, внутри задачи сценарии идут по одному. Упала проверка — задача красная, GitHub присылает письмо о неудачном запуске
(включить: GitHub → Settings → Notifications → Actions → «Send notifications for failed workflows only», галочка Email). Снимки упавших задач — во вложениях прогона (`smoke-shots-…`, 7 дней). Вручную: Actions → «Проверки (smoke)» → Run workflow.

## Шаблон 1. Проверки в браузере (`qa/smoke.mjs`)
Группы по сценариям (набор целиком ≈ 20 минут; разбивка на четыре чата ≈ 5–8 минут на каждый):
- A: `desktop-ru`, `phone-ru`; B: `desktop-en`, `phone-en`, `rules`, `graph`, `combat`; C: `dash`, `split`, `spore`, `armored`, `intro`,
  `danger`, `rotate`, `production`; D: `lose-ru`, `lose-en`, `win-ru`, `win-en`, `fullgame`; E: `towers`.
- Команды субагенту: `npm run build && npm run build:qa`, затем по одному `node qa/smoke.mjs --tag=par-<буква> --only=<сценарий>`.
- Формат ответа: «ГРУППА / КОММИТ / ИТОГ (ПРОЙДЕНО или ЕСТЬ ОШИБКИ — N из M) / СЦЕНАРИИ / ОШИБКИ / ПРЕДУПРЕЖДЕНИЯ КОНСОЛИ / ЗАМЕТКИ 📝 /
  ВИДНО НА СКРИНШОТАХ / НЕ УДАЛОСЬ ПРОВЕРИТЬ». Упал сценарий — перезапуск один раз; упал дважды — ошибка.
- Счёт при раздельном запуске больше, чем при полном (проверка консоли считается в каждом запуске).

## Шаблон 2. Бот баланса (`qa/bot.mjs`)
- Профили: `novice` (новичок), `average` (средний), `strong` (сильный: человеческие несовершенства), `expert` (особо сильный: прежний «сильный» кругов 1–2).
  Цели баланса (обновлены после PR #12, см. `docs/balance-history.md`, «Цели круга 13»): новичок проигрывает рано; средний — на 8–14-й волне; сильный до конца не доходит (или с потерями);
  **особо сильный без потерь не выигрывает** (проигрывает поздно или побеждает, потеряв 2–3 жизни); без Шприца, Шипучки или всех, кроме Таблеток, особо сильный заметно хуже. (Прежняя цель «особо сильный выигрывает без потерь» снята.)
- Команда: `npm run build:qa`, затем `node qa/bot.mjs --profile=<novice|average|strong|expert> --runs=10 --speed=2 --canvas --tag=<тег>`;
  «нужна ли башня»: `--profile=expert --runs=5 … --exclude=<syrup|fizz|syringe|pill>`; проба чисел без правки файла: `--cfg=путь:число,…`.
  **С 30 волнами (этап 3б) партия ≈ 6–8 минут с `--canvas` (раньше на 12 волн — 2,3): чат на 5 партий ≈ 35–40 минут, на 10 — больше часа, делить по 5 партий.** Каждая команда дольше 10 минут: запускать в фоне (`nohup`) и опрашивать лог.
- Чаты (круг замеров): 1 — novice ×10; 2 — average ×10; 3 — strong ×10; 4 — expert ×10; 5 — expert ×5 с `--exclude=syrup`, затем `--exclude=fizz`;
  6 — expert ×5 с `--exclude=syringe`, затем `--exclude=pill`. (В кругах 1–2 «strong» значил то, что теперь `expert`.)
- **«Лестница сложности»** (подбор чисел без правки файла; **числа HP ниже — старые, до этапа 3б: пересчитать от нынешних HP в `src/config.ts`**): те же профили на трёх уровнях прочности бактерий через `--cfg`:
  L0 — без `--cfg`; L1 — `--cfg=types.rod.hp:5,types.splitter.hp:4,types.armored.hp:18,types.spore.hp:3`;
  L2 — `--cfg=types.rod.hp:6,types.splitter.hp:5,types.armored.hp:21,types.spore.hp:4`; L3 (вдвое прочнее L0) —
  `--cfg=types.rod.hp:8,types.splitter.hp:6,types.armored.hp:28,types.spore.hp:5`. Теги — `<профиль>-L0/L1/L2/L3`.
- Если бот менялся с прошлого круга (новый профиль и т. п.), чат сначала делает пробную партию `--profile=<профиль> --runs=1 --speed=4 --canvas`
  (≈ 1–3 минуты) и, если бот упал, присылает текст ошибки, не начиная основной прогон.
- Формат ответа: «ЧАТ / КОММИТ / КОМАНДЫ / ИТОГОВАЯ ТАБЛИЦА БОТА (дословно) / ПАРТИИ (дословно) / ПРОБЛЕМЫ / НЕ УДАЛОСЬ».
- Во время прогона `src/` и `qa/` не менять («сборка устарела»). Бот остановился с ошибкой (код ≠ 0, `console.error`, `cfg:`, зависание) —
  выписать текст и перезапустить один раз; повторилось — это результат.

## Шаблон 3. Бот после этапа 3б, шаг 2 (пробная партия — «не упал ли бот»)
Бот научился понимать луч Шприца (8 направлений, «особо сильный» поворачивает башню тапами) — писался без запуска. Один чат, ≈ 15 минут:
`npm run build:qa`, затем по одному `node qa/bot.mjs --profile=<novice|average|strong|expert> --runs=1 --speed=4 --canvas --tag=try-<профиль>`
(партия ≈ 2–4 минуты; команды дольше 10 минут — в фоне). Ответ: «ЧАТ / КОММИТ / ПРОФИЛЬ → результат партии (одна строка бота) / ⚠ расхождения и
ошибки (дословно) / НЕ УДАЛОСЬ». Особенно важны строки «⚠ Шприц в …: ждали направление …» (бот не смог повернуть башню) и любая ошибка консоли.

## Шаблон 4. Починка проверок `smoke` под этап 3б (один чат; правит только `qa/`)
Набор устарел (см. `docs/technical-notes.md`). Один чат прогоняет сценарии по одному, красные разбирает: если ожидание устарело — правит `qa/smoke.mjs`
(и `qa/lib.mjs`); если похоже на настоящую ошибку игры — НЕ правит `src/` и `src/config.ts`, а описывает. Сценарий `towers` переписывается под новые правила:
Сироп — лужа (капля летит в точку дорожки впереди бактерии, лужа живёт `puddleSec`, бактерия в ней идёт ×`slowFactor`, поверх старой лужи новая не кладётся);
Шипучка — малый взрыв; Шприц — луч (направление `towers[].aim`, тап по башне = +1 шаг, очередь `beamPulses` ударов по всем на линии, урон с учётом брони);
рой, бегун, лекарь, броня; `lifePool`. В конце — `git pull --rebase origin claude/serene-rubin-x3t2gu`, коммит, push.

## Шаблон 6. Круг 8 (коммит см. ответ агента): «особо сильный» A/B по стартовым монетам, «сильный» и «средний»
Два коротких чата (≈ 15–25 минут): 1) `expert` ×4 с настройками по умолчанию (старт 250 монет) и `expert` ×4 с `--cfg=economy.startCoins:180` (теги `r8-expert-250`, `r8-expert-180`);

### Б1 «Бот жив и уровни 5, 10» (≈ 40 мин)
**Модель и усилие:** Sonnet 5.5 (claude-sonnet-5-5), усилие medium.

```
Ты — исполнитель замеров для игры «Таблетки против бактерий» (HTML5, Phaser; репозиторий Aurinox-eng/1). В проекте ничего не меняй и не коммить: ты только запускаешь бота и точно пересказываешь результат.

3. ЗАДАЧА: по одной партии: node qa/bot.mjs --profile=novice --runs=1 --speed=4 --canvas --tag=try15-novice; то же для average, strong, expert (теги try15-average, try15-strong, try15-expert); затем node qa/bot.mjs --profile=expert --runs=1 --speed=4 --canvas --level=5 --tag=try15-l5 и то же с --level=10 --tag=try15-l10. Особенно важно: строил ли «особо сильный» Сироп на уровне 1, Шипучку на уровне 5 и Шприц на уровне 10 (число построек по видам), все «⚠», ошибки консоли, на какой волне закончилась каждая партия. Балансом партии на --speed=4 не оцениваются.
4. Команды бота идут дольше 10 минут: запускай каждую в фоне (nohup … > лог 2>&1 &), лог опрашивай каждые 3–5 минут до конца. Бот упал (код ≠ 0, «cfg:», «партия зависла», «Игра не запустилась») — выпиши текст ошибки дословно, перезапусти команду один раз; повторилось — это результат, не чини.

В конце удали qa/bot-results/ и логи.
6. Ответ одним блоком, без пересказа своими словами: ЧАТ / КОММИТ / КОМАНДЫ / ТАБЛИЦА БОТА (дословно) / СТРОКИ ПАРТИЙ (дословно) / merges, levels, timeline, число построек по видам и время первой постройки каждого вида, lifeLossWaves — по каждой партии / ПРОБЛЕМЫ (все «⚠», ошибки консоли, зависания) / НЕ УДАЛОСЬ.
```
