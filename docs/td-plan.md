# План работ: tower defense

План одобрен владельцем («ок» — сессия перехода на жанр) с правками: **поле горизонтальное, красная линия слева;
у башен разные способы стрельбы; боты и проверки только через субагентов, владельцу — итоговая таблица.**
Правила — `docs/td-rules.md`. Каждый этап по правилу проекта: план → одобрение → код; в конце — сборка, прогон `qa-tester`,
скриншоты, команда для игры, коммит и push в рабочую ветку. Pull request — только по просьбе владельца.

## Самые большие этапы
4, 6 и 7 — больше всего баланса. Глубокая система при ≈10 башнях без бота-замерщика не сбалансируется — поэтому бот
переписывается на этапе 3.

## Как работаем (решение владельца)
- **Боты и проверки запускают только субагенты** (`qa-tester` — проверки в браузере; `game-designer` — бот и баланс).
  Главный агент их не запускает и не пересказывает их сырой вывод.
- **Владельцу в конце этапа — одна итоговая таблица** («Что сделано / Проверка / Результат / Что нужно от вас»), без логов,
  чисел бота и технических подробностей. Если что-то не проверено — строка в таблице так и скажет.
- Сохранение прогресса до этапа 9 — в браузере игрока; на Яндекс Играх без входа в аккаунт он может пропасть — решает SDK.
