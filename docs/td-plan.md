# План работ: tower defense

План одобрен владельцем («ок» — сессия перехода на жанр) с правками: **поле горизонтальное, красная линия слева;
у башен разные способы стрельбы; владельцу — итоговая таблица.** Боты и проверки идут через GitHub Actions (решение владельца, круг 15).
Правила — `docs/td-rules.md`. Каждый этап по правилу проекта: план → одобрение → код; в конце — сборка, проверки на GitHub, снимки, команда для игры, коммит и push в рабочую ветку. Pull request — только по просьбе владельца.

## Самые большие этапы
4, 6 и 7 — больше всего баланса. Глубокая система при ≈10 башнях без бота-замерщика не сбалансируется — поэтому бот
переписывается на этапе 3.

## Как работаем (решение владельца)
- **Боты и проверки идут через GitHub Actions** (`balance.yml` — замер ботами, `checks.yml` — `smoke` на каждый push; инструкция — `docs/bot-prompts.md`). Агент запускает замеры сам и читает итоговую таблицу; отдельные чаты не нужны; локально в контейнере агента боты не запускаются.
- **Владельцу в конце этапа — одна итоговая таблица** («Что сделано / Проверка / Результат / Что нужно от вас»), без логов,
  чисел бота и технических подробностей. Если что-то не проверено — строка в таблице так и скажет.
- Сохранение прогресса до этапа 9 — в браузере игрока; на Яндекс Играх без входа в аккаунт он может пропасть — решает SDK.
