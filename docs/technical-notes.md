# Технические решения и особенности

Подробности, вынесенные из CLAUDE.md. Описывают код после перехода на tower defense (этап 1). Старая игра с падающими
бактериями — коммит `3b913a3`; её механика и подбор баланса описаны в `docs/balance-history.md` (история).

## Бот-замерщик баланса (`qa/bot.mjs`, этап 3)
Играет **целые партии** в тестовую сборку (`npm run build:qa`, режим `?qa`) только через интерфейс: колесо мыши (карта целиком), клик
по кнопке башни, клик по клетке. Состояние (`__pvb.getState()/getGraph()/cellToClient()`) нужно ему только для решений; игру он не
подкручивает. Запускает **`game-designer`** (боты по одному, не параллельно: на 4 ядрах контейнера параллельный запуск не ускоряет).
- **Запуск:** `node qa/bot.mjs [--profile=novice|average|strong|expert|all] [--runs=N] [--speed=2] [--canvas] [--exclude=syrup,fizz,syringe,pill]
  [--cfg=путь:число,...] [--tag=имя] [--seed=N] [--max-game-sec=1200] [--verbose] [--shots]`. Справка — `node qa/bot.mjs --help`.
  **`--canvas` (рекомендуется): игра рисуется через canvas вместо WebGL (`?qa&canvas`, только в тестовой сборке и dev; в игровой
  сборке параметр не работает — проверено) — партия идёт в 2,1 раза быстрее при том же результате.**
  Примеры: `node qa/bot.mjs --profile=all --runs=10 --tag=base` (весь замер); `node qa/bot.mjs --profile=strong --runs=10 --exclude=fizz --tag=no-fizz`
  (нужна ли Шипучка); `node qa/bot.mjs --profile=average --runs=10 --cfg=towers.fizz.price:100,waves.pauseSec:8 --tag=try1`
  (подбор чисел без правки файла). Пробная партия: `--profile=all --runs=1 --speed=4`.
- **Профили:** `novice` — только Таблетки, клетки наугад (где с дорожки хоть что-то достаёт), не больше 6 башен, покупает, как только
  хватает монет; `average` — по кругу [Таблетка, Таблетка, Сироп, Таблетка, Шипучка, Шприц], ждёт монет на очередную, клетка наугад
  из лучших 15 % по охвату; **`expert` («особо сильный»)** — по кругу [Таблетка, Сироп, Шипучка, Шприц, Таблетка, Шипучка, Сироп, Шприц], лучшая
  клетка именно для этой башни (охват с весом «сколько бактерий там идёт», Шипучка — у слияний веток, Шприц — клетка и направление луча с наибольшей
  длиной дорожки под лучом; после постановки бот поворачивает Шприц тапами на лучшее направление, башни по сети, а не кучкой), ждёт монет на дорогую башню до 30 игровых секунд, решает каждые 2 с — **это бывший «сильный» кругов замеров 1–2
  без изменений**; **`strong` («сильный»)** — тот же порядок и оценка клеток, но с человеческими несовершенствами: решает раз в 3 с, ждёт
  монет на дорогую башню 8 с (потом берёт что по карману — больше дешёвых Таблеток), клетку берёт наугад из лучших 15 % по оценке (не меньше четырёх), шум оценки 12 %, **не знает приёмов**: Шипучку ставит без упора на узлы слияния, у Шприца не учитывает, сколько бактерий идёт по каждой ветке, и не поворачивает его
  (остаётся направление, которое игра выбрала при постановке сама).
  Исключённую `--exclude` башню профиль пропускает.
  Константы профилей (доли, пороги, списки покупок) — в шапке `qa/bot.mjs`.
- **Как играет:** решения не чаще раза в 2 игровые секунды (одна покупка за решение), опрос состояния каждые ≈120 мс реального времени.
  «Охват» клетки — длина дорожки в радиусе башни (по точкам рёбер из `getGraph`); «вперёд» — у отрезка дорожки расстояние до организма
  больше, чем у клетки (считается по графу так же, как `remainingNear` в `src/level.ts`; бот сверяет это с `tower.remaining` из игры и
  пишет «⚠», если разошлось). Свободные клетки — по правилу игры (центр ближе `pathWidth/2 + 0.45·tile` к любой точке ребра); если тап
  не поставил башню — клетка «плохая», выбирает другую. Клетки у верхнего/нижнего края при минимальном приближении бот двигает пальцем.
- **Что печатает:** строку на партию (результат, волна, жизни, убито/дошло, монеты, башни по типам, игровое и реальное время) и таблицу
  по профилям (доля побед, потерянные жизни, волна гибели, средние башни, монеты в конце, время). Файл `qa/bot-results/<тег>.json`
  (по партиям: покупки, жизни по волнам, «срезы» по волнам; дописывается после каждой партии). `Ctrl+C` — доиграть партию и напечатать итог.
- **Остановки:** любая `console.error`, ошибка страницы или предупреждение `cfg:` (игра не поняла подмену) — бот останавливается
  с сообщением (код 3), чтобы не выдать замер исходных чисел за замер подменённых. Партия дольше `--max-game-sec` игровых секунд —
  результат `timeout`; игровое время не идёт 30 реальных секунд — партия считается зависшей и повторяется один раз.
- **Время и точность:** ВАЖНО, `--speed` выше 2 делает замер грубее: кадр игры считается не длиннее 50 мс реального времени,
  умноженных на `speed` (при speed 4 шаг до 0,2 игровой секунды — башни и снаряды «дёргаются» крупнее). В облачном контейнере игра
  рисуется программно (≈ 12–14 кадров/с, от размера окна не зависит), поэтому игровое время идёт ≈ 0,9 с на реальную секунду при
  speed 2 и ≈ 1,7 при speed 4: **партия (≈ 255 игровых секунд) ≈ 5 минут при speed 2 и ≈ 2,5–4 минуты при speed 4**; замер «3 профиля × 10
  партий» ≈ 2,5 часа при speed 2. **С `--canvas` партия при speed 2 — ≈ 2,3 минуты (139 с вместо 289 с), «3×10» ≈ 70 минут**; игровое
  время и итог партии при этом совпадают (256,7 с и 256,8 с, те же 246 убитых и 225 монет). Параллельные браузеры в одном контейнере не
  ускоряют; ускоряет только разнесение по разным чатам (у каждого свой контейнер).
- **Ограничения бота:** нет улучшений/продажи (их нет в игре до этапа 4); выбор клеток — эвристика (оптимального игрока нет); сколько
  урона нанесла каждая башня, бот не видит (в `getState` нет статистики по башням) — «нужна ли башня» проверяется сравнением профилей
  с `--exclude`; цены, радиусы и стиль стрельбы бот читает из `src/config.ts` (плюс подмена `--cfg`), в `getState` их нет.

## Общая инфраструктура
- Экран 1280×720 (16:9), режим масштабирования `Phaser.Scale.FIT`: помещается целиком на любом устройстве, по краям — тёмные поля.
  `base: './'` в `vite.config.ts` — относительные пути обязательны (игра открывается из подпапки `/1/` на Pages и из zip Яндекса).
- Поворот телефона и смена окна: Phaser иногда знает новый размер страницы, но не перестраивает экран
  (воспроизводилось в эмуляции), поэтому `main.ts` сам вызывает пересчёт (`refit`) после `resize`/`orientationchange`.
- Игровое время: `dt = min(deltaMs, 50) / 1000 * TIME_SCALE`. Один кадр не длиннее 50 мс в расчётах движения — после
  сворачивания вкладки объекты не «прыгают»; если кадр длинный, за него может выйти несколько бактерий (не больше 10).
  Всё, что зависит от игрового времени (движение, паузы башен, волны), считается по `dt`; твины и вспышки — по реальному.
- Защита от случайного рестарта после конца уровня (`gameOver.restartLockMs`) и от мгновенного снятия паузы (250 мс) — по
  реальным часам (`performance.now`): игровые часы Phaser отстают, когда кадры тормозят.
- Звуки — свои, `src/sound.ts` (WebAudio, тоны рисуются кодом): аудио создаётся при первом касании/клике — в консоли нет
  предупреждений и звук работает на iPhone. Звуковая система Phaser выключена (`audio.noAudio` в `main.ts`).
  Громкость — `feedback.soundVolume` в `config.ts` (0 — без звука). Есть: выстрел, попадание, уничтожение, башня поставлена,
  «нельзя», новая волна, победа, потеря жизни, проигрыш.
- Язык: `src/lang.ts` берёт язык из браузера; в игровой сборке подмены через адрес нет. На этапе 9 главнее будет язык из SDK Яндекса.
- Иконка вкладки — встроенная SVG в `index.html` (иначе 404 favicon в консоли). `<title>` в `index.html` запасной,
  его заменяет текст из i18n.
- Телефон вертикально: игра горизонтальная, поэтому при `(orientation: portrait) and (pointer: coarse)` поверх неё показывается
  блок `#rotate` из `index.html` («Поверните телефон горизонтально», текст ставит `main.ts` из i18n), а игровое время и жесты
  стоят (`src/orientation.ts`). На компьютере с мышью этого нет. Требования Яндекс Игр к ориентации не проверены (этап 9).
- Текст рисуется с `resolution: 2` (чёткий при масштабировании экрана и приближении карты).
- В окружении агента `node_modules` может быть пустой: `PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1 npm install` (браузер уже лежит в
  `/opt/pw-browsers`).

## Две сборки и режим проверки (?qa)
- `npm run build` → `dist/` — ИГРОВАЯ; `npm run build:qa` → `dist-qa/` — ТЕСТОВАЯ.
- `QA_ENABLED = import.meta.env.DEV || MODE === 'qa'`. В игровую сборку код `?qa` не попадает вообще; проверка
  `qa/smoke.mjs` убеждается, что в ней нет `?qa`, подмены `?cfg=` и `?lang=`. Это важно для этапа 9: иначе рекорд и рекламу
  можно накрутить из адресной строки.
- Возможности `?qa`: `?qa&canvas` — рисовать через canvas (быстрее на машине без видеокарты); `window.__pvb` — `getState()` (снимок состояния, `DebugSnapshot` в `src/debug.ts`: монеты, жизни, волна,
  башни и бактерии (у обоих `remaining`; у бактерий `slowed`), камера, положение кнопок панели (`ui.towerButtons`), счётчики
  откликов (`effects.blasts`) и замедлений `slows`), `worldToClient / gameToClient / cellToClient`
  (перевод координат мира/игры/клетки в координаты страницы — для мыши и касаний Playwright), `speed=N` (ускорение времени),
  `cfg=раздел.параметр:число` (подмена числа из `config.ts`, вложенные пути через точки), `lang=en`.
- Проверки запускает субагент `qa-tester` (`npm run qa -- --tag=<имя>`); скрипт стирает папку `qa/screenshots/<имя>` перед
  прогоном. Не использовать теги `stage-1`, `stage-1b` (там скриншоты старой игры) и `td-1-mockup` (макет).

## Как устроена игра сейчас (этапы 1–2)
- **Карта** 18×14 клеток по 103 px + зона организма 150 px слева (мир 2004×1442 px). Рисуется один раз обычным canvas в четыре
  текстуры (`src/mapArt.ts`; куски не больше 2048 px — безопасно для старых телефонов; плотность = максимальное приближение,
  поэтому карта чёткая). При перезапуске уровня текстуры используются повторно.
- **Данные уровня** — `src/level.ts`: размер карты, **граф дорожек** (узлы и рёбра, «корневая система»: 3 входа, 3 выхода, 4 развилки,
  5 слияний), стартовая точка камеры. `src/pathing.ts` строит каждое ребро как плавную кривую Безье с горизонтальными касательными на
  концах (поэтому рёбра в узлах стыкуются гладко): по ней и рисуется дорожка, и ходят бактерии (позиция = точка на расстоянии `s` от
  начала ребра). В конце ребра бактерия выбирает следующее **случайно и поровну** среди рёбер, выходящих из узла (развилка).
  `remainingAtEnd` ребра — сколько пикселей до организма по самому короткому пути: по нему башни выбирают «ближайшую к организму».
  Клетки, задетые дорожкой (центр ближе полуширины дорожки + 0,45 клетки), — `PATH_TILES`, ставить башни там нельзя: 94 клетки из 252, свободных 158; запас нужен, чтобы основание башни не заходило на полосу дорожки. Ещё закрыты `BLOCKED_TILES` (дальше `map.buildMaxDistPx` от дорожки) — осталось 115 свободных.
- **Камера** — `src/cameraRig.ts`: не камера Phaser, а масштабирование и сдвиг контейнера с миром; панель справа лежит поверх и
  не двигается (окно карты 1080×720). Карта не выезжает за край; минимальное приближение (0.54) — по ширине карта помещается целиком.
- **Жесты** — `src/mapGestures.ts`: один палец/мышь — сдвиг, два пальца — щипок и сдвиг, колесо — приближение вокруг курсора
  (учитывает `deltaMode`: Firefox шлёт строки, а не пиксели), касание без сдвига (≤ `tapMaxMovePx` = 22 px экрана игры ≈ 12 px на
  стекле телефона 844×390, ≤ `tapMaxMs`) — тап. Когда палец выходит за порог, карта сразу догоняет его. Тапом не считается:
  жест с двумя пальцами, касание, отменённое системой (`wasCanceled`), палец, отпущенный над правой панелью. Касания правой
  панели в жесты не попадают: её кнопки — интерактивные зоны Phaser.
- **Башни** — таблица `CONFIG.towers`, одна строка — одна башня (Таблетка, Сироп, Шипучка, Шприц). Колонки: цена, радиус, урон, пауза,
  скорость снаряда, `targeting` (как бьёт: `radius`, `area`, `puddle`, `beam`), `side` (`both` / `forward` / `back`), `blastRadius`,
  `slowFactor`/`slowSec`, `puddle*` (радиус, время жизни, вынос вперёд), `beam*` (число ударов в очереди, пауза, длина, полуширина).
  Выбор цели — `Tower.pickTarget`: из бактерий в радиусе (плюс радиус самой бактерии) и с нужной стороны берётся та, которой до
  организма ближе всего по дорожкам. «Вперёд/назад»: `Tower.remaining` (расстояние до организма по дорожкам от ближайшей точки сети,
  `level.remainingNear`) сравнивается с `Bacterium.remaining`: у «впереди» оно больше, у «позади» меньше. Что делает выстрел — в
  `GameScene.fire` (возвращает, состоялся ли выстрел: пауза башни идёт только после состоявшегося):
  `radius`/`area` → `Projectile` (летит за целью; если цель уже уничтожена другим выстрелом, долетает до её последнего места; у `area` —
  `explode`: круг касается тела бактерии и бьёт всех), `puddle` → `GroundShot` (капля летит в точку дорожки впереди бактерии на
  `puddleLeadPx`, но в радиусе башни; не бросается, если там уже лужа или летит капля) → `Puddle` (живёт `puddleSec`; `updatePuddles` каждый кадр
  замедляет всех в ней через `Bacterium.slow`, ещё `slowSec` после выхода), `beam` → очередь `BeamBurst`: каждые `beamGapMs` удар
  `beamPulse` по всем, кого `Tower.beamHits` находит на линии (полоса от башни по направлению `aim`, длина `beamLengthPx`,
  полуширина `beamHalfWidthPx` плюс 0,7 радиуса бактерии). Попадание — `damageBacterium` → `Bacterium.hit(урон)` (**броня:** урон =
  max(урон·`combat.armorMinShare`, урон − `armor`)). Рисунок башни и снаряда — по `id` (`createTowerArt`, `drawShot`). Новая башня = строка в
  таблице + рисунок + тексты (`towerX`, `tagX`) в `i18n.ts` + строка в `TOWER_TEXT` панели (без неё проект не соберётся).
- **Направление луча Шприца:** 8 направлений (`level.AIM_STEPS`, номер 0 — вправо, дальше по часовой стрелке, шаг 45°). При постановке
  `level.bestBeamDirection` выбирает то, где под лучом больше всего дорожки; тап по башне с лучом (`GameScene.onTap`) поворачивает её на
  шаг (`Tower.rotateAim`, звук `sfx.rotate`). Пунктир направления — `drawAimLine`; призрак при выборе Шприца показывает пунктир по лучшему
  направлению вместо круга радиуса. В состоянии для проверок — `towers[].aim`.
- **Лечение и пачки:** лекарь (`healRadius`, `healPerSec`) лечит в `GameScene.applyHealing` всех, кроме себя; рой (`spawnGapSec`) и любой тип
  с этим числом выходит «блоком»: до `waves.packMax` штук подряд с паузой `spawnGapSec`, все по одному входу (очередь волны —
  `SpawnItem`). Дробный урон по жизням (рой 0,25) копится в `lifePool` (в состоянии `lifePool`), целая жизнь списывается при 1.
- **Ввод башни**: кнопки панели — по одной на строку таблицы; выбор показывает «призрак» с радиусом; для Сиропа, Шипучки и
  Шприца внизу пишется, как они бьют (`GameScene.towerInfo`); после первого Шприца в партии — сообщение «тапните по Шприцу — повернуть».
- **Волны** — `CONFIG.waves`: первая через `firstDelaySec`, между волнами `pauseSec`, пауза между выходом бактерий сокращается от
  `intervalStartSec` до `intervalEndSec`. **Состав** волн — таблица `waves.list` (сколько бактерий каждого типа); типы выходят в
  случайном порядке, а тип, которого ещё не было, — первым и один (сигнал `sfx.newType` и сообщение сверху). Вышли все и на карте
  никого — победа. Число волн — `waves.total` (не больше строк списка).
- **Особенности типов** (колонки таблицы `CONFIG.types`): палочка — **рывки** (`dash*`: раз в `dashEverySec` секунд на `dashSec` секунд
  скорость ×`dashFactor`, у каждой палочки свой сдвиг часов); делящаяся — при гибели **кокки** (`splitCount` штук на расстоянии
  `splitGapPx` вдоль дорожки на том же ребре); спора — **глушит башни** (`disableSec`, `disableRadius`: башня темнеет, не стреляет;
  каждую башню одна спора глушит один раз, очередь луча глушённой башни обрывается); бронированная — прочная, 2 жизни, **броня** (`armor`);
  рой — пачка (`spawnGapSec`), дробный урон жизням; бегун — просто очень быстрый (`speedFactor`), вытянутая «капля»; лекарь — **лечение**
  (`healRadius`, `healPerSec`).
- **Панель** — `src/ui/Panel.ts`: волна и прогресс, монеты, жизни (сердца), четыре кнопки башен (значок, название, способ, цена; цена красная, если не хватает монет), пауза, подсказка
  «◀ Организм» у левого края (когда организм за краем экрана; мигает красным, если бактерия ближе `ui.dangerDistancePx`),
  всплывающие сообщения сверху и постоянная подсказка снизу.
- **Отклик** — `src/effects.ts`: вспышка при попадании, частицы и «+монеты» при уничтожении, кольцо при постановке башни;
  при потере жизни — красная вспышка на ВСЁМ экране и тряска (организм может быть за краем экрана).
- Бактерии рисует `bacteriumArt.ts` (форма, толщина оболочки и трещины зависят от типа и оставшегося HP).
- Башню можно поставить при любом приближении (решение владельца); при сильном отдалении клетка на телефоне мельче пальца.

## Особенности рабочей среды (для агента)
- Облачный контейнер ≈ 4 ядра, программный WebGL (~14 fps). Он может перезапуститься и убить фоновые задачи; долгие замеры лучше
  запускать так, чтобы потерю не жалко.
- Определения субагентов подхватываются только при старте сессии — в текущей сессии инструкции давать в самом промпте.
- Write/Edit требуют предварительного Read файла (после `git checkout`/`cp` — «file modified since read»; обход: heredoc/python).
- `pkill -f` использовать с шаблоном `[q]a/smoke.mjs`, иначе убьёшь собственную команду.
- Инструменты GitHub (`mcp__github__*`) подгружаются через ToolSearch; `gh` в облаке нет. Отправка меток (tags) на GitHub из
  облака не проходит (403).
- Chromium для Playwright лежит в `/opt/pw-browsers`; `qa/lib.mjs` умеет его искать.
- Режим `?qa&canvas` строже WebGL: отрицательный радиус круга в canvas бросает исключение («The radius provided (-0.2) is negative»), а в WebGL
  рисунок молча ломается. Так нашли ошибку круга 3: оболочка бронированной (14 HP) стала толще радиуса тела. Теперь толщина оболочки — доля радиуса
  (`bacteriumArt.shellWidth`), а внутренние радиусы не меньше 1. При смене HP в `config.ts` поглядеть на `bacteriumArt.ts`.
- После слияния PR ветка `claude/...` уже «старая»: `git fetch origin main && git rebase origin/main`, затем
  `git push --force-with-lease` (это своя рабочая ветка, не чужая). Новый PR — только по просьбе владельца.
- GitHub Pages кэширует страницу до 10 минут (`max-age=600`): владелец может видеть старую версию после слияния. Проверять
  сервер: `version.txt` рядом с игрой и имя файла бандла.
- Автоматический хук «есть незакоммиченные изменения» требует коммитить и пушить; для промежуточных состояний — коммит
  «Промежуточная точка (WIP)», потом нормальный коммит.
- В файлы с `&&`-цепочкой `git add` не подставлять удалённые пути: команда упадёт, и коммит не сделается.
- Дубли ключей в `src/i18n.ts` после массовой замены: проверять `npm run typecheck` (ключ в `ru` без `en` не соберётся).
