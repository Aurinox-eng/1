# Технические решения и особенности

Подробности, вынесенные из CLAUDE.md. Касаются текущего кода (механика падающих бактерий). Часть решений —
общая инфраструктура (масштабирование, ввод, звук, сборки, QA) и останется при любой смене жанра; часть — про
конкретную механику и может устареть.

## Общая инфраструктура (пригодится при любом жанре)
- Поле 720×1280 (9:16), режим масштабирования `Phaser.Scale.FIT`: помещается целиком на любом экране, по краям — тёмные поля.
  `base: './'` в `vite.config.ts` — относительные пути обязательны (игра открывается из подпапки `/1/` на Pages и из zip Яндекса).
- Стрелять/нажимать можно по любой точке экрана, в том числе по тёмным полям вокруг поля (на высоких телефонах нижняя
  полоса — там, где лежит палец). Phaser `pointerdown` по холсту + DOM `pointerdown` на `window`; положение по
  горизонтали берётся из точки нажатия.
- Несколько касаний (`activePointers: 3`): у каждого пальца своя пауза между выстрелами (`pill.cooldownMs`), считается
  по реальным часам (`performance.now`, `cooldownMs / TIME_SCALE`) — на слабом телефоне пауза не растягивается.
- Игровое время: `dt = min(deltaMs, 50) / 1000 * TIME_SCALE`. Один кадр не длиннее 50 мс в расчётах движения — после
  сворачивания вкладки объекты не «прыгают»; если кадр длинный, за него может появиться несколько бактерий (не больше 10).
- Защита от случайного рестарта после проигрыша (`gameOver.restartLockMs`) — по реальным часам (`performance.now`):
  игровые часы Phaser отстают, когда кадры тормозят (из-за этого рестарт раньше иногда не срабатывал).
- Поворот телефона и смена окна: Phaser иногда знает новый размер страницы, но не перестраивает поле
  (воспроизводилось в эмуляции), поэтому `main.ts` сам вызывает пересчёт (`refit`) после `resize`/`orientationchange`.
- Звуки — свои, `src/sound.ts` (WebAudio, тоны рисуются кодом): аудио создаётся при первом касании/клике — в консоли нет
  предупреждений и звук работает на iPhone. Звуковая система Phaser выключена (`audio.noAudio` в `main.ts`).
  Громкость — `feedback.soundVolume` в `config.ts` (0 — без звука).
- Язык: `src/lang.ts` берёт язык из браузера; в игровой сборке подмены через адрес нет. На этапе 4 главнее будет язык из SDK Яндекса.
- Иконка вкладки — встроенная SVG в `index.html` (иначе 404 favicon в консоли). `<title>` в `index.html` запасной,
  его заменяет текст из i18n.
- Скриншоты/текст: поле 720×1280 на телефоне с 3× разрешением растягивается примерно в 1,6 раза — текстуры и текст делать с запасом чёткости.
- Под счётом, сердцами и временем — тёмная подложка `HUD_PLATE_H = 104` (бактерии выезжают из-под неё). Шрифт HUD 38,
  сердца с шагом 58: «Score: 99999» до 258 px, сердца с 272 px; время не ближе 488 px против 448. «+очки» не выше
  170 px от верха (иначе наезжают на подложку).

## Две сборки и режим проверки (?qa)
- `npm run build` → `dist/` — ИГРОВАЯ; `npm run build:qa` → `dist-qa/` — ТЕСТОВАЯ.
- `QA_ENABLED = import.meta.env.DEV || MODE === 'qa'`. В игровую сборку код `?qa` не попадает вообще; проверка
  `qa/smoke.mjs` убеждается, что в ней нет `?qa`, подмены `?cfg=` и `?lang=`. Это важно для этапа 4: иначе рекорд и рекламу
  можно накручивать из адресной строки.
- Возможности `?qa`: `window.__pvb.getState()` (снимок — `src/debug.ts`, `DebugSnapshot`), `speed=N` (ускорение времени),
  `cfg=раздел.параметр:число` (подмена числа из `config.ts`, вложенные пути через точки), `lang=en`.
- Бот и проверки останавливаются при устаревшей сборке (mtime `src` новее `dist-qa`) и при опечатке в `--cfg` (код выхода 2).
- `npm run qa -- --tag=<имя>` стирает папку `qa/screenshots/<имя>` перед прогоном. Не использовать тег `stage-1b`
  (там скриншоты бота). Проверок — 82: телефон/компьютер, RU/EN, WebGL, тап по тёмным полям, два пальца, поворот,
  «зависание», сценарий «типы бактерий», `listeners` (лишние обработчики тапов), игровая сборка без `?qa`.

## Механика падающих бактерий (текущий код)
- Тип задаётся таблицей `CONFIG.types` (hp, speedFactor, points, hitPoints, lifeDamage, introSec, weight, radius, length,
  selfSplitSec, zigzagPx, zigzagSec). Порядок появления — `introSec`: кокк 0, палочка 15, делящаяся 30, бронированная 45, спора 60.
- Попадание считается честно: таблетка (прямоугольник, растянутый на путь за кадр) касается любого из кругов, из которых
  состоит тело бактерии (палочка — цепочка из трёх, делящаяся — из двух). Красной линии касается самая нижняя точка тела (`bottom`).
- HP на бактерии: толщина оболочки пропорциональна оставшемуся HP, число трещин — полученному урону (`bacteriumArt.ts`).
- Делящаяся делится сама, если её не задевали `selfSplitSec` секунд; попадание сбрасывает отсчёт. Последние `split.warnSec`
  секунд она пульсирует и растягивается — предупреждение. Распад делящейся → два кокка (`SPLITS_INTO`).
- Новый тип появляется в `introSec` в одном экземпляре (со звуковым сигналом), и `spawn.introPauseSec` секунд других новых нет.
- Бронированная у линии отнимает 2 жизни (`lifeDamage`).
- Отклик — `src/effects.ts` (вспышка с ADD-смешением, частицы, «+очки», тряска при делении, красная вспышка при потере жизни)
  и `src/sound.ts` (hit / destroy / split / selfSplit / arrival / lifeLost / lose). Все числа отклика — `CONFIG.feedback`.

## Особенности рабочей среды (для агента)
- Облачный контейнер ≈ 4 ядра, программный WebGL (~14 fps). Он может перезапуститься и убить фоновые задачи (подбор баланса
  терялся); долгие замеры лучше запускать так, чтобы потерю не жалко.
- Определения субагентов подхватываются только при старте сессии — в текущей сессии инструкции давать в самом промпте.
- Write/Edit требуют предварительного Read файла (после `git checkout`/`cp` — «file modified since read»; обход: heredoc/python).
- `pkill -f` использовать с шаблоном `[q]a/bot.mjs`, иначе убьёшь собственную команду.
- Инструменты GitHub (`mcp__github__*`) подгружаются через ToolSearch; `gh` в облаке нет.
- Chromium для Playwright лежит в `/opt/pw-browsers`; `qa/lib.mjs` умеет его искать.
