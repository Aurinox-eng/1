# План новой цели сложности (12 октября 2026; «ок» владельца получен 13 октября, замер идёт)

Решение владельца принято; 13 октября владелец одобрил план, уровни 5 и 10 — лестницей с 1-го уровня. Кривая и награда вносятся в `src/config.ts` после пробной серии (подстройка `hpScale`). Текст цели — `docs/decisions.md` («Решения владельца 12 октября (вечер)», п. 5); замеры, на которых построен план, — `docs/balance-history.md` («Поздний рост прочности»).

## Цель

Уровень не проходится с первой попытки никем, включая «особо сильного» (`expert`). Игрок проигрывает, получает очки ДНК, покупает улучшения и проходит уровень за несколько попыток. Режим бота `--ladder` (улучшения покупаются между попытками):
- 1-я попытка: `expert` гибнет на 8–12-й волне, `strong` на 6–9-й, побед нет ни у кого;
- каждая следующая попытка: `expert` +3–5 волн, `strong` +2–4;
- первая победа: `expert` на 4–6-й попытке, `strong` на 6–10-й.

Прежние цели 5б («18–24» и «27–29,5») заменены. Ступенька роста прочности с 16-й волны под цель не подходит (сжимает разницу между наборами и не даёт улучшениям двигать игрока): нужен плавный рост с первых волн, без ступеньки.

## Что даёт проигрыш (по `src/config.ts`, `qa/bot.mjs`)

- `meta.dna.perWave` = 5 очков за каждую пройденную волну (номер волны минус 1), `winBonus` = 15; звёзды (`levels.starDna` = 10 за новую звезду) только при победе. Проигрыш на 8–12-й волне — 35–55 очков, у `strong` на 6–9-й — 25–40.
- Бот между попытками покупает жадно (`damage → coins → lives → reward`, затем остальные улучшения). 45 очков = урон 1–2-го уровня (+20 %) и стартовые монеты 1-го уровня (+50). Цены урона 1–7-го уровня (нарастающим итогом): 15, 35, 60, 95, 140, 195, 265; +10 % урона за уровень.
- По прежним замерам (`docs/balance-history.md`, круг А-4) около 105 очков давали около +1 волны на уровнях 3–6 при нынешней кривой — нужно в разы больше.

## Модель шага (оценка; параметр `r` неизвестен, его даст пробная серия)

Прирост волн за попытку ≈ ln(прирост силы игрока) / ln(r), где `r` — во сколько раз быстрее силы игрока растёт суммарная прочность волны. Сила = только урон и награда (оценка снизу), старт `expert` — 10-я волна, `strong` — 7,5. Расчёт повторяется коротким скриптом по ценам из `meta.upgrades`; в репозитории его нет.

| Награда за волну | `r` | Шаги `expert` по попыткам | Первая победа `expert` / `strong` |
|---|---|---|---|
| 5 (сейчас) | 1,04 | 4,6 / 3,9 / 1,8 / 2,9 / 2,7 | 8-я / 13-я |
| 5 | 1,06 | 3,1 / 2,6 / 1,2 / 1,1 / 1,9 | нет за 14 |
| 10 | 1,04 | 7,9 / 5,3 / 4,2 / 2,5 | 6-я / 8-я |
| 10 | 1,06 | 5,3 / 3,6 / 2,0 / 1,7 / 1,6 | нет за 14 |
| 15 | 1,04 | 8,6 / 6,2 / 2,8 / 2,4 | 5-я / 6-я |

С нынешней наградой шаг ≥ 3 волн держится 2–3 попытки, потом падает из-за роста цен улучшений. Предложение: `meta.dna.perWave` 5 → 10 (`winBonus` без изменений).

## Кривая

Множитель прочности бактерий волны с номером `n` (с единицы): `hpScale × (1 + perWave × max(0, n − fromWave) + latePerWave × max(0, n − lateFromWave))` (`GameScene.waveHpMul`). Суммарная прочность волны = бюджет волны × множитель. Бюджет уровней 2–10: `b0 + (b1 − b0) × ((n − 1) / 29)^1,5`, уровень 5 — `[10, 1336]`. `waves.hpScale` (2,5) общий для всех уровней; `perWave`, `fromWave`, `latePerWave`, `lateFromWave` и `hpBudget` — у каждого уровня в `levels.specs` (уровень 1 — `waves.hpGrowth*` и рукописный `waves.list`).

## Замер

- **Режим `--ladder`** (`qa/bot.mjs`; в Actions — `ladder.yml`, поля `profile`, `lanes`, `k`, `to_level`, `speed`, `cfg`; файл запроса `.github/ladder-request.json`): дорожка проходит уровни подряд, на уровне играет до `k` партий до первой победы, после каждой партии получает очки и покупает улучшения. `expert` и `strong`, по 6 серий, до 10 попыток на уровень, уровни 1, 5, 10. В итоге для каждой серии: волна гибели в каждой попытке и номер попытки с первой победой.
- **Пробная серия — первой (запущена 13 октября на `fdcf314`, П-Б: `hpScale` 5; `ladder.yml` run `38354273350` — `expert`, run `38354276482` — `strong`; `k` 10, 1 дорожка, `speed` 2; результаты не прочитаны)**: уровень 1, по одной серии `expert` и `strong`, `k` = 10, `to_level` = 1; кривая через `cfg` (например `waves.hpScale:5,waves.hpGrowthFromWave:4,waves.hpGrowthPerWave:0.1,waves.hpGrowthLatePerWave:0`, награда — `meta.dna.perWave:10`).
- **Подстройка по пробной серии**: если `expert` на 1-й попытке гибнет на волне `w0` вместо 10, умножить `hpScale` на отношение суммарной прочности 10-й волны к `w0`-й по таблице; если шаг < 3 волн — награду выше или кривую плавнее; `strong` из-за разброса бота (ранние гибели на 10–12-й волне даже без роста) оценивать по 6 сериям.
- **Открытый вопрос владельцу — уровни 5 и 10**: «холодный старт» (`--from-level 5` без состояния, очков ДНК 0: быстро, но игрок на 5-м уровне приходит с очками прошлых уровней) или лестница с 1-го уровня через `ladder.yml` (реалистично, но дольше: по описанию workflow партия 35–60 минут реального времени). Рекомендация: лестница.
