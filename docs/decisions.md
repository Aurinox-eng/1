# Журнал решений и открытых вопросов

Кто решает: **владелец проекта** (не программист). Технические детали решает агент и коротко объясняет простыми словами.
Крупные решения — по правилу «план → одобрение → код».

## Принятые решения владельца

### Смена жанра: tower defense (последнее решение)
Владелец сообщил, что игра переходит к жанру **tower defense**.
**Подробности в сессию не передавались.** Не определены: правила нового жанра; что будет с текущей механикой
(падающие бактерии, тап-выстрел, 3 жизни, пять типов); что из кода переиспользуется; как это связано с деревом
улучшений и с этапами 2–5. В репозитории нет ни одной строки про tower defense — ничего не придумывать.
→ Первый шаг следующей сессии: **обсудить с владельцем и согласовать план**, код не писать до одобрения.

Что заведомо не привязано к жанру и, скорее всего, переиспользуется (это предположение агента, а не решение владельца):
масштабирование и ввод (`main.ts`), звук (`sound.ts`), отклик (`effects.ts`), i18n, сборки `build`/`build:qa`, режим `?qa`,
QA-скрипты и бот (бота придётся переписать под новую механику), автопубликация на Pages.

### Обойма (лимит выстрелов) — отвергнута

пункт 3 (счёт, время и сердца на тёмной подложке) — сделан. Замеры — `docs/balance-history.md`.

### Дерево улучшений — отложено (только проект, код не писать)
Владелец: «Дерево улучшений пока не делаем. Сначала шаг 1б». Позже (после шага 1б) просил «Делай шаг 2» — агент понял это как
пункт 2 шага 1б, ответа на уточнение не было; дерево улучшений **не начато**. При смене жанра оно, возможно, потеряет смысл или
изменится. Требования владельца сохранены здесь на случай возврата:
- валюта «антитела»: даётся за уничтоженных бактерий, копится между партиями;
- 3 ветки по 4–5 уровней (12–15 улучшений):
  - огневая мощь: урон, скорострельность, крит;
  - особые таблетки: пробивание, двойной выстрел, взрыв по площади, замедление;
  - защита: дополнительная жизнь, щит у линии, медленный старт;
- первое улучшение доступно после 1–2 партий; партия с улучшениями — 60–90 с;
- дерево — данные в отдельном файле (не разбросано по коду);
- отдельно продумать, где уместна rewarded-реклама (этап 4);
- проект писать в `docs/upgrades.md`, показать владельцу таблицей и ждать «ок». Код не писать.

### Прочие решения
- Площадка — Яндекс Игры. Технологии: Phaser 3.90 (НЕ обновлять до 4), TypeScript, Vite. Графика и звуки — кодом, без внешних файлов.
- Поле 720×1280 (9:16), масштабирование FIT. Управление — тап/клик по любой точке экрана (в т. ч. по тёмным полям).
- Тексты — только через `src/i18n.ts`, сразу на русском и английском. Баланс — только в `src/config.ts`.
- PR — только по просьбе владельца. Автопубликация на GitHub Pages — только с `main`.
- Играть в игру бот-профилями нужно по одному и со `--speed` не выше 2.

## Открытые вопросы
1. **Tower defense:** правила, судьба текущей механики, порядок работ (см. выше). Главный блокер.
2. Цель «к 30-й секунде на экране ≥ 8 бактерий» не выполнена (получается 3–5). Варианты: «волны» (правка кода) или снизить цель
   до ~5. **Актуально, только если текущая механика остаётся.**
3. Баланс текущей механики не проверен на живых игроках (кокк идёт до линии ≈ 5,5 с; таблетка 14 px; пауза 250 мс).
4. Не проверено на настоящем телефоне: поворот, два пальца, плавность, звук, iPhone (Safari) — в автотестах только Chromium.
5. Этапы 2–5 (стартовый экран и рекорд; графика и звук; SDK Яндекса; zip) не начаты; после решения о жанре их надо пересмотреть.
6. ~~Pull request #4 не слит~~ — [Aurinox-eng/1#4](https://github.com/Aurinox-eng/1/pull/4) слит в `main` по просьбе владельца
   (коммит `3b913a3`). Актуальная версия выкладывается на https://aurinox-eng.github.io/1/ автоматически (`/version.txt`).
7. Описания агентов `.claude/agents/game-designer.md` (цели баланса шага 1б) относятся к механике падающих бактерий —
   при смене жанра их нужно переписать.
